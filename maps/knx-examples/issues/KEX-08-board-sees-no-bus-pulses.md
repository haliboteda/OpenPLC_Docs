# 板子的 KNX_RX 上看不到总线脉冲：先查哪一边

Type: grilling
Opened: 2026-10-10
Status: resolved
Blocked by: -

## Question

2026-10-10 实测（[KEX-04-findings.md](../KEX-04-findings.md)「2026-10-10」）：板子 KNX 端子 29.5 V、PH12 = 1，隧道往总线发报文时，PA10 上没有一个约 35 µs 的低脉冲，只有约每秒 100 个不到 1 µs 的毛刺；板子发的帧 ETS 也看不到。代码的极性与 [HARDWARE-FACTS.md](../../../docs/hardware/HARDWARE-FACTS.md)「KNX 接口」一致，探针不经 KNX 库直接读引脚，所以问题在 PA10 之前。

| 做法 | 代价 | 能分清什么 |
|---|---|---|
| ST-Link 烧 2026-09-09 跑通过的工装 KNX 固件，同一块板 `pt.start knx mode=frames` | 要重烧 bootloader，扇区 15（认领）要保住 | 这块板的硬件现在还通不通 |
| 示波器量 STKNX pin 23 / U13 输出 / PA10，同时隧道发报文 | 一次示波器（TODO 第 3 节本来就在等） | 断在 STKNX、光耦还是 MCU 引脚 |
| 换另一块板跑同一个探针 | 要第二块板 | 是这块板还是这一批板 |

## 已做

2026-10-10 第一种跑完：工装固件在这块板上同样收发都不通（[KEX-04-findings.md](../KEX-04-findings.md)「2026-10-10」），**是这块板的硬件，不是 KNX 库**。探针在 PB14 打脉冲，PA10 收不回自己的回波，发送、接收两路至少断一路，STKNX 本身也可能坏。示波器（三个点量不到）和第二块板（没有）两条路现在都走不了，等板子修好或有新板再定到器件。

## 怎么算答完

用户选定一种并跑完；断点落到一个器件或一段代码上。

2026-10-11 第三种：换上新板，`T3-13` 收、发两个方向都通（板子打印隧道写来的帧；板子发的帧隧道收到、板子收到应答）。**坏的是旧板，不是这一批板。** 旧板断在哪个器件仍没定，要修旧板时再量。

2026-10-11 稍后：新板**发送**也不通了 —— 板子打印 `KNX TX ...`，ETS 总线监视器和网关隧道都看不到 1.1.1 的帧；接收照常（温度传感器 9.0.12 → 7/5/4 每帧都收到）。软件复位后不变。全部重新上电、总线 29.5 V 后仍不通。库的计数器（ST-Link 读内存）：`tx_ok` 0、`tx_failed` 每发一帧加 1、`collisions` 只有 1、`rx_bad` 0。（PH12 读到 0 不算数：库没配这个脚，它停在模拟模式。）同一固件一小时前 `T3-13` 收发都通过。 3 分钟每 5 秒发一帧：36 帧里 1 帧收到应答，其余没有，是时通时断，不是全断。

2026-10-11 换烧工装 0.10.0（STM32 直接出 TP1 位时序，不经 Arduino KNX 库）：20 秒发 21 帧，隧道一帧没收到，自己也没收到回波；接收正常（坏字符 0、`w_avg=35`）。**新板坏在发送一路，是硬件，不是 KNX 库。** 整片 flash 测前已备份，测完写回并逐字节核对一致（写回要用 `mode=UR`，HOTPLUG 擦不掉工装正在跑的扇区）。

2026-10-11 傍晚：用户修过硬件后，新板**接收通、发送仍不通** —— COM12 敲 `w 1/0/1 0` / `w 1/0/1 1`，板子打印 `KNX TX 1.1.1 -> 1/0/1 ...` 后约 65 ms 报 `not acknowledged`，ETS 组监视器一帧没有。修了哪里待用户补。下一步：示波器同时量 PB14 和 STKNX pin 24（两边不共地），发一帧，看脉冲断在 MCU、U12/R94 还是 STKNX。

## Answer

2026-10-12 定：用户修过硬件后新板 KNX 收发都通（用户：「knx功能已经通了」）。同日 COM12 跑 `KNX_BusMonitor` 实测：收到 9.0.12 → 7/5/4 的温度帧；板子 1.1.1 发 3 帧 `b 7/5/4 0D 2D`，3 帧都 `acknowledged`。坏的器件和修法待用户补。

## 引出了什么新的未知

旧板坏在哪个器件没定，修旧板时再量。
