# 执行器被总线写时不回报状态，用例怎么判它动了

Type: grilling
Opened: 2026-10-12
Status: resolved
Blocked by: -

## Question

测试盒的执行器 9.0.10 被写 1/0/1 时不往 7/3/1 回报状态，只在按手动键时回报（[KEX-04-findings.md](../KEX-04-findings.md)「2026-10-12」）。`$TEST/tools/run_knx_box.py` 里有 4 处要等这个回报，在现在的测试盒上一定失败：`T3-13`（总线监视收发）、`T3-16`（DI1 控制执行器）、`T3-18`（按温度联动）、`T3-19`（IP 路由器转发）。

另外，`T3-17` / `T3-18` 由脚本往温度组地址写假温度，而真传感器 9.0.12 每 5 秒也往 7/5/4 写一次，两边会互相覆盖。

| 做法 | 代价 | 推荐 |
|---|---|---|
| A 改判据：执行器动没动改成人看 A1 的灯（问 y/n），脚本只判总线上有板子发的那一帧和它的应答 | 每条多一次人工确认 | ✅ 不动执行器原有的配置 |
| B 用 ETS 重新给执行器下载，让状态对象在被写时也发送 | 要导入 Lingg & Janke 的产品数据，覆盖执行器原有的配置 | |
| C 脚本发完后主动读 7/3/1（GroupValue.Read） | 执行器的状态对象带 R 标志才会回答，没核实 | 先试一次再定 |

假温度的问题：给板子对象 21 另关联一个只有脚本写的温度组地址，或者测之前请人断开传感器。

## 怎么算答完

用户选定一种；然后先改 [M3](../../../docs/modules/M3-app-runtime.md) 的判据，再改脚本。

## Answer

2026-10-12 定：A（用户：「其他问题和工作单开子窗口继续」，按推荐）。判据在 [M3-app-runtime.md](../../../docs/modules/M3-app-runtime.md) 第 3 节。

| 问题 | 定了什么 | 一句理由 |
|---|---|---|
| 执行器动没动 | 不等 7/3/1；脚本只判总线上板子（`T3-19` 是板子那条隧道）发往 1/0/1 的那一帧，执行器动作由人看 A1 的灯亮 / 灭答 y/n | 不动执行器原有的配置 |
| 应答 | 只有 `KNX_BusMonitor` 打印 `KNX TX acknowledged`，所以只在 `T3-13` 判；其他例程不打印，隧道也看不到 TP 层应答 | 判据只写看得见的 |
| 温度 | 不写假温度，不改 ETS 配置。`T3-17` 不发读请求，等传感器自己往 7/5/4 写的那一帧来对比；`T3-18` 取板子收到的室温 x，从 RS232 输入 `t <x-1.0>` / `t <x+1.0>` 让它开 / 关 | 用户 2026-10-12：「你不需要考虑假板子，现在真的测试环境就是有这样的数据，你就针对现在测试环境进行修改。」 |
