# 用例怎么判、人做哪几步

Type: grilling
Opened: 2026-10-03
Status: resolved
Blocked by: KEX-04, KEX-05

## Question

每个例程一条真板用例。哪些步骤脚本经网关自己发、自己看，哪些只能人在 ETS 里做（下载应用、看组监视器）；用例进 `run_examples.py` 的表，还是另起一个脚本；编号用哪个。人做的步骤照 [要人配合的步骤脚本怎么问](../../core-examples-on-board/issues/EXB-05-how-does-the-script-ask-for-a-human-step.md) 的做法。

用户 2026-10-09 认可的用例清单（板子为 TP 设备 0x07B0；ETS 经测试盒的 IP 网关接到总线）：

| 顺序 | 测什么 | 人做的 | 怎么判 |
|---|---|---|---|
| 1 | ETS 给 IP 网关、温度传感器、继电器开关执行器、PLC 设地址并下载 | 逐台按编程键，ETS 里下载 | ETS 显示成功；PLC 串口打印地址和 configured |
| 2 | ETS 控制开关执行器 | — | 脚本经网关发开关组地址，收到执行器的状态回报；继电器响（人听）；PLC 监视打印这一帧 |
| 3 | PLC 控制开关执行器 | — | PLC 发开关组地址，脚本收到执行器的状态回报 |
| 4 | 温度传到 PLC | — | PLC 发读请求，传感器回复，PLC 打印温度，和 ETS 组监视器一致 |
| 5 | ETS 控制 PLC | — | 脚本写 PLC 的继电器对象，PLC 继电器吸合并回报状态 |
| 6 | 按温度联动 | 捂热传感器或把阈值设在当前温度下 | 超阈值后 PLC 发开关组地址，执行器动作并回报 |

每条用例有对应的 Arduino 例程；通用例程 `KNX_BusMonitor` 打印总线报文、发报文。

## 怎么算答完

每条用例定下步骤、每步的判据（自动还是人判）、脚本位置和用例编号。

## Answer

2026-10-10 定（用户：「就按照刚才你给我纠正后的方案，准备。要必要的代码和测试」；用例清单是用户 2026-10-09 认可的那张）。判据逐条在 [M3-app-runtime.md](../../../docs/modules/M3-app-runtime.md) 第 3 节 `T3-13`–`T3-20`。

| 问题 | 定了什么 | 一句理由 |
|---|---|---|
| 脚本 | 另起 `$TEST/tools/run_knx_box.py`，编译、上传、读串口、问人复用 `run_examples.py` 的函数 | KNX 用例要同时看串口和总线，`run_examples.py` 的表只看串口 |
| 总线一侧怎么看 | 脚本经测试盒接口开一条 xknx 隧道，自己发组报文、收总线上的报文（用户 2026-10-15：测试目的下脚本可以往总线发） | [测试脚本能不能经 IP 网关直接收发组报文](KEX-04-can-the-script-talk-through-the-ip-gateway.md) 已证实走得通；ETS 同时连着也行 |
| 人做什么 | ETS 里编程和关联组地址、按 BOOT0、给 DI1 加撤 24 V、听继电器响；照 [要人配合的步骤脚本怎么问](../../core-examples-on-board/issues/EXB-05-how-does-the-script-ask-for-a-human-step.md) | 其余都由脚本经隧道和串口判 |
| 联动怎么触发 | 不往总线写温度：从 RS232 把阈值设在板子收到的室温下 / 上 1 °C（2026-10-12 改，见下） | 测试盒的真传感器每 5 秒写一次室温，假温度会被覆盖 |
| 编号和对应例程 | `T3-13` `KNX_BusMonitor`（用例 2，加串口发报文）；`T3-14` ETS 编程（用例 1）；`T3-15` `KNX_Switch`（用例 5）；`T3-16` `KNX_Inputs`（用例 3）；`T3-17`、`T3-18` `KNX_Temperature`（用例 4、6）；`T3-19` `KNX_IPRouter`；`T3-20` `KNX_Analog`（2026-10-10 加，用户认可非 1 位例程） | 一个例程至少一条用例 |
| 顺序 | `T3-13` 不用 ETS，先跑；`T3-14` 编程之后依次 `T3-15`–`T3-18`、`T3-20`；`T3-19` 最后 | 后面的用例依赖 ETS 下载过的配置 |

ETS 里的组地址（脚本参数的默认值，可改）。2026-10-12 起 ETS 只给板子编程，测试盒三台设备保留已有配置（用户：「你就针对现在测试环境进行修改」），所以「ETS 里关联到」只指板子的对象：

| 组地址 | 是什么 | ETS 里关联到 |
|---|---|---|
| 1/0/1 | 执行器开关（测试盒已有） | 板子对象 13（`KNX_Inputs` 的 DI1）和对象 22（`KNX_Temperature` 的温度开关） |
| 7/3/1 | 执行器状态（测试盒已有） | 不关联，不进判据 |
| 7/5/4 | 温度（传感器已有） | 板子对象 21 |
| 3/0/1 | 板子继电器 1 开关 | 板子对象 1 |
| 3/0/2 | 板子继电器 1 状态 | 板子对象 2 |
| 4/0/1 | 板子 AI1（mV） | 板子对象 23 |
| 4/0/2 | 板子 AI2（mA） | 板子对象 24 |
| 4/0/3 | 板子 AO1 设定值（mA） | 板子对象 25 |
| 4/0/4 | 板子 AO2 设定值（mA） | 板子对象 26（没有用例用到） |

2026-10-12：测试盒已有的执行器状态是 7/3/1、温度是 7/5/4（[KEX-04-findings.md](../KEX-04-findings.md)「2026-10-12」），脚本默认值跟着改；执行器状态不进判据，温度用例只用真传感器的室温（[KEX-11](KEX-11-actuator-does-not-report-status-on-bus-write.md)）。

⚠️ 经网口重传同一个例程后 ETS 配置还在（2026-10-12，`KNX_Temperature` 两次）；换成另一个例程后还在不在没核实：板子打印 `not configured` 时脚本提示在 ETS 里重新下载板子。
