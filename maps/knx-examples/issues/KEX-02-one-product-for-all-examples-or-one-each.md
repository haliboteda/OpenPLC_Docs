# 所有例程共用一个产品，还是一个例程一个

Type: grilling
Opened: 2026-10-03
Status: resolved
Blocked by: -

## Question

ETS 下载时按产品里的组对象表配置板子，例程里 `getGroupObject(n)` 的编号必须和产品一致。可以做一个整板产品（像现有那份，26 个对象覆盖继电器、DO、DI、AI、AO），所有例程各用其中一部分；也可以每个例程配一个只含自己对象的小产品。用户要在 ETS 里导入几次、例程之间切换时要不要重新下载、以后维护几份产品文件，都取决于这个。

## 怎么算答完

定下产品的个数，以及每个产品的组对象表：编号、名字、数据类型、通信 / 读 / 写 / 发送标志。

## Answer

2026-10-03 定（用户：按推荐）：

| 问题 | 定了什么 | 一句理由 |
|---|---|---|
| 几个产品 | **一个整板产品**，所有例程共用，各用其中一部分 | 导入一次；换例程只重传 sketch —— 上传只擦镜像占用的扇区（`$BOOT/IAPServer/IAP_server.c:96`），ETS 配置在扇区 14 留着，不用重新下载 |
| 放哪些对象 | **只放例程要用的**：6 个继电器、8 个 DI；DO、AI、AO 等迷雾里的例程定了再加 | 只做必要的 |
| 编号 | 继电器 1–12，DI 13–20；以后的类型从 21 往后排，**已有编号永不改** | 改号会让用户 ETS 工程里的组地址关联错位 |
| 继电器 | 每个两个对象：开关（总线写入）+ 状态（板子发送、可读），DPT 1.001 | KNX 开关执行器的标准做法，ETS 和可视化靠状态对象显示真实状态 |
| DI | 每个一个对象，DPT 1.001，变化时发送、可读 | — |

组对象表（产品文件 `$ETSPROD/OpenPLC_TP.xml` 照这张表生成）：

| 编号 | 名字 | 标志 |
|---|---|---|
| 1, 3, 5, 7, 9, 11 | 继电器 1–6 开关 | 通信、写 |
| 2, 4, 6, 8, 10, 12 | 继电器 1–6 状态 | 通信、读、发送 |
| 13–20 | DI 1–8 | 通信、读、发送 |
