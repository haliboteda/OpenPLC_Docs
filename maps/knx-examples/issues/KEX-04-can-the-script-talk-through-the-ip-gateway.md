# 测试脚本能不能经 IP 网关直接收发组报文

Type: research
Opened: 2026-10-03
Status: resolved
Blocked by: -

## Question

ETS 经网络上的 KNX IP 网关接到总线（用户 2026-10-03 说）。如果网关支持 KNXnet/IP 隧道，PC 上的脚本也能经它往总线发组报文、收板子发出的报文、读设备的物理地址 —— 用例里大部分步骤就能自动判，只剩 ETS 下载应用要人做。网关的型号、IP、支不支持隧道、同时允许几条连接（ETS 占一条），都还不知道。

2026-10-03 第一轮：网关是 HDL 的 KNXnet/IP 设备（10.32.2.129），这台 PC 当时不在那个网段，见 [KEX-04-findings.md](../KEX-04-findings.md)。

## 怎么算答完

- 在局域网上用 KNXnet/IP 搜索请求找到网关，记下型号、IP、支持的服务和隧道连接数
- 从脚本经网关发出一个组报文并收到网关的确认
- 写明 ETS 开着时脚本还能不能连

## Answer

2026-10-09 定（现场结果在 [KEX-04-findings.md](../KEX-04-findings.md)「2026-10-09 测试盒网关」）：

| 问题 | 结论 |
|---|---|
| 网关是什么 | 测试盒里的「KNX IP Interface 732 secure」，192.168.0.30，物理地址 9.0.1，8 个隧道槽；PC 在同一网段时组播搜索就能找到 |
| 脚本能不能经它发组报文 | 能：UDP 隧道写组地址，网关回确认 |
| ETS 开着时脚本还能不能连 | 能：第一条隧道开着时第二条照样连上 |
| 用什么库 | xknx，它管隧道的序号、重发和心跳，也带读物理地址这类设备管理操作 |
