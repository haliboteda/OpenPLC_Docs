# 03 · 格子上到底印什么

Type: grilling
Opened: 2026-09-11
Status: resolved
Blocked by: -

## Question

面板每个通道的格子上，标签显示成什么，工程师才不用换算？

起因是用户的原话：**「上回我想开启 DO3 并且设置 pwm，但是在上位机上我完全不知道怎么弄，对应不上。」**

现在的行为（`$TOOL/internal/ptproto/caps.go:185`）：**只显示端子号**。`dout` 第 3 路印的是 `A05`，而用户找的是 "DO3"。`TerminalLabels()` 推不出来时返回 nil，面板退回显示通道号 —— 设计上刻意不编造，这一点是对的。

## 要定的几件事

1. **两个都显示吗？** 候选格式：`DO3 · A05`、`DO3 (A05)`、上下两行。用户按 DO 编号想问题，接线的人按端子号想问题。
2. **通道号的名字从哪来？** 现在 `pt.caps` 里没有「DO」这个词，只有端口名 `dout` 和通道序号。是从端口名推（`dout` → `DO<n>`），还是固件新增一个字段？**推导会在 `ain`/`aout`/`din`/`relay` 上遇到不同的叫法。**
3. **一块硬件占多个端子怎么显示？** 继电器是触点对，6 通道 12 端子，固件这时走 `terms=` 显式给标签。两个端子怎么并排印。
4. **`TerminalLabels()` 返回 nil 时**（推不出来）显示什么，措辞是什么。
5. 改动落在哪一层：`caps.go` 推导、面板 `index.html` 渲染、还是固件多给一个字段。**多一个字段就多一处要和硬件对齐的抄件**，代价要说清。

## 注意

这张 ticket **不依赖 01 / 02** —— 不管端子号本身对不对，「格子上该印什么」是独立的决定，可以并行推进。但**实现要等 02**，否则等于把错的标签排得更好看。

---

## 用户 2026-09-11 定的（部分闭合）

**原话**：「DO3 就用这个；如果你说的是上位机面板页面上应该写什么，就写 `Klemmenbezeichnungen-R` 里面的端口名就行，**不需要告诉具体那个脚号**。我平时缩写会将 digital out 写成 DO，AI/AO DI 都是缩写。」

### 决定

**面板格子上印功能名，不印端子号。**

| | |
|---|---|
| 现在 | `A05`（端子号） |
| 改成 | **`DO3`**（功能名） |

功能名的出处是 `Hardware/Klemmenbezeichnungen-R.pdf` 上印的名字，按用户的习惯缩写：

| 图上印的 | 面板写 |
|---|---|
| Digital Out 1–8 | `DO1`–`DO8` |
| Digital IN 1–8 | `DI1`–`DI8` |
| Analog IN 1/2 | `AI1` / `AI2` |
| Analog OUT 1/2 | `AO1` / `AO2` |

### 这条决定的两个连带后果

1. **`term=` 不再是标签的来源。** `TerminalLabels()`（`$TOOL/internal/ptproto/caps.go:185`）现在从 `term=` 推标签，改完之后它不再喂给格子。端子号是否还要在 caps 里保留（给报告、给判据用），单独定。
2. **RS485 那处端子号错误不再会误导面板用户**，但数据本身仍然是错的。优先级从「会坑人」降到「数据错」—— 见 `02-firmware-term-vs-hardware.md`。

### 还没定（本 ticket 未闭合的部分）

- **继电器怎么缩写**：图上是 `Relais Out 1–6`。用户给了 DO / DI / AI / AO，没给这个。
- **单通道的信号端口标签**：`rs485` / `can` / `rs232` / `knx` 在图上是 `RS485 A`、`RS485 B`、`CAN H`、`CAN L`、`RS232 TxD`、`RS232 RxD`、`KNX +`、`KNX −` —— 这些不是「第 n 路」，是具名信号。原样照抄还是缩写。
- **图上没有对外端子的端口怎么办**：`eth`（图上叫 `LAN`）、`usb`（`USB`）、`sd`（`SD Karte`，德语）、以及 `sdram` / `temp` / `pwm` / `soak` 这些根本不在图上的。
- **名字从哪来**：固件的 `terms=` 字段已经能显式给标签（继电器在用），改它即可，不必新增字段。但「DO1–DO8」这种规则性的要不要上位机推导，省掉固件改动 —— 要权衡多一处抄件 vs 多一处推导规则。

---

## Answer

2026-09-11 定。

**面板格子上印功能名，不印端子号。** 名字取自 `Hardware/Klemmenbezeichnungen-R.pdf`，按用户的习惯缩写。

| 端口 | 图上印的 | **面板写** |
|---|---|---|
| `dout` | Digital Out 1–8 | `DO1`–`DO8` |
| `din` | Digital IN 1–8 | `DI1`–`DI8` |
| `ain` | Analog IN 1/2 | `AI1` / `AI2` |
| `aout` | Analog OUT 1/2 | `AO1` / `AO2` |
| `relay` | Relais Out 1–6 | **`Relay 1`–`Relay 6`** |
| `rs485` | RS485 A / RS485 B | **照抄** |
| `can` | CAN H / CAN L | **照抄** |
| `rs232` | RS232 TxD / RS232 RxD | **照抄** |
| `knx` | KNX + / KNX − | **照抄** |
| `eth` | LAN | 照抄 |
| `usb` | USB | 照抄 |
| `sd` | SD Karte | 照抄 |
| `sdram` | （图上没有） | `SDram` |
| `temp` | （图上没有） | `temperature` |

**不显示端子号**（`A05`、`C09` 这些）。用户原话：「不需要告诉具体那个脚号。」

### 连带后果

1. `TerminalLabels()`（`$TOOL/internal/ptproto/caps.go:185`）不再喂给格子。端子号是否仍保留在 caps 里（报告、判据用）单独定。
2. RS485 的端子号错误不再出现在屏幕上 —— 从「会让人接错线」降级为「caps 里的错数据」。仍要改。
3. 固件的 `terms=` 字段已能显式给标签（`relay` 在用），改它即可，**不必新增字段**。

### 分出去的问题

用户在回答时指出「pwm 应该是 do 里面的一项，soak 也是一个针对某个接口的测试项」—— 那不是标签问题，是**面板怎么组织端口列表**的结构问题，已分到 `06-port-list-structure.md`。
