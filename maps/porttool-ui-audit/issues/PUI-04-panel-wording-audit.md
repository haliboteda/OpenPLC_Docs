# 04 · 面板逐卡片过一遍提示与参数

Type: prototype
Opened: 2026-09-11
Status: open
Blocked by: PUI-02, PUI-03

## Question

面板上 14 个端口的卡片，**哪些地方要看文档才用得明白**？

判据是一句话：**一个没读过 `PORTTOOL-FLOW.md` 的硬件工程师，能不能只看面板就完成这个端口的测试。**

## 每张卡片要过的几项

| 过什么 | 具体 |
|---|---|
| **参数名** | `mv=1:500`、`loop=ctrl`、`mode=quad`、`src=hw`、`ga=31/7/255` 这类，面板上直接抄了协议字面量的地方，有没有人话解释 |
| **判据在哪** | 这个端口「通过」的标准是什么，面板上看不看得到。⚠️ 判定一律在上位机（DECISIONS 22），所以判据的出处是 `$TOOL/internal/ptcheck/`，不是固件 |
| **哪些数不是判据** | `loop=ctrl` 的端口，回报的那三个计数只说明控制口活着，**不是该端口的判据**（DECISIONS 9）。必须和读数分区显示 |
| **一次性动作 vs 会话 vs 交权** | 三类端口的操作语义不一样（`pt.run` 回来、`pt.handover` 不回来），按钮措辞有没有暴露这个区别 |
| **坑要不要写在卡片上** | 例：`dout` 是软件 PWM 不是硬件定时器通道，两两共用比较单元；`freq` 封顶 2000 Hz。这些现在只在 `PORTTOOL-FLOW.md` 里 |
| **失败信息** | 超时和判定失败是分开记的（ptreport 三条规矩），面板上读起来分不分得清 |

## 怎么做

**不要一次改 14 个。** 先拿 `dout` 做一张，给用户看，形状认可了再铺开 —— 这就是这张 ticket 标 `prototype` 的原因。

## 注意

`$TOOL/internal/ptpanel/web/index.html` 里页面源码和渲染结果是两回事：H5 的断言不能用 `document.body.textContent`（源码里就有 `crc=raw` 这些字样），要等渲染出来的节点。改完页面记得这条。

## 2026-09-11 用户实测反馈（两条）

1. **「页面上英文的地方没有翻译成中文。」** → 规矩已落进 `IAPTranfer_Tool/CLAUDE.md`「面板上的字一律说大白话」：**人看的字一处英文都不留**，只有日志窗里的协议原文是例外。
2. **「我选了 DO3，占空比 50%，点了一下开始直接就结束了，结果是失败。」** → 见下，是缺陷，已修。

## 缺陷：改了参数之后，判据还照旧判

**复现**（模拟板，1.41 秒）：勾 DO3、占空比 50，按「开始测试」→
`ch1 eq 100 %：读到 （no field "ch1"…）；ch8 eq 100 %：读到 （no field "ch8"…）`

**根因**：判据来自方案 `station6-poweron.json` 的 `high-side-out` 步骤，写死 `ch1 eq 100`、`ch8 eq 100`；
固件只回报**勾了的通道**（`porttool_dout.c` 的 `PortCmd_FormatPairs` 按 mask 输出）。
人一改通道或占空比，那两条判据必然落空 —— **好板子照报失败**。

同一类坑 2026-09-08 犯过一次（relay 默认 `on=1:0` 让好板子判失败），当时只修了「按方案预填」，
没管「人改完之后怎么办」。

**修法**（用户 2026-09-11 选的 A+B）：
- 面板实时比对「当前参数」和「方案参数」，不一致时**按钮改口**成「按我改的参数跑（不出结论）」，
  并说清哪一项从什么改成了什么
- 同时**不再判**（`judge()` 里对会话帧直接跳过；`pt.run` 目标不受影响，它不带卡片上的参数）
- 加「恢复方案参数」一键还原
- ⚠️ 连带修掉一个更早就存在的毛病：**参数值原来只活在输入框里**，而每来一帧
  `renderPanel()` 都会把 `#panelbody` 整个重建 —— 会话一跑起来，人刚敲的数就被下一帧抹掉。
  现在存在页面状态 `edited` 里（和 `picked` / `testing` / `dodi` 同一类）

## 中文化：改了哪些层

| 层 | 怎么处理 |
|---|---|
| 参数名 / 枚举值 / 读数字段 / `pt.run` 目标 | `index.html` 四张词表（`PARAM_CN` / `VALUE_CN` / `FIELD_CN` / `TARGET_CN`），**协议原值进 `title` 悬停**，发出去的命令一个字没变 |
| 端口名 | 卡片头改用 `PORT_LABEL`；协议名收进卡片上一行带标签的「协议名」，端口行只留悬停 |
| `Klemmblock` | → 「端子排」 |
| 判据那句话 | Go 那边照旧英文（命令行和 CSV 报告要它），`/api/judge` 多带结构化的 `check` + `missing`，**中文在面板自己拼**（`checkCN` / `failCN`） |
| 每个端口的「接线 / 方法 / 什么算过」 | `PORT_HELP` 全部重写成大白话，不再抄协议字面量 |

**不译**：型号与网络名（`LAN8742A`、`ISO1044`、`LM50`、`STKNX`、`MDIO`）、端子号（`A03-A10`、`C10/C11`、`J1`）、
文件系统名（`FAT32`、`exFAT`）、Windows 给的串口描述、方案文件名、日志窗里的协议原文。

## 顺带查出来的三处

1. **`usb` 端口根本没有说明条目** —— 卡片上显示「这个端口还没有写说明……`help/ports.json` 里还没有对应条目」。
   ⚠️ **`help/ports.json` 这个文件从来就不存在**（说明住在 `index.html` 的 `PORT_HELP` 里），
   那句话既泄漏内部路径又是假的。已补 usb 条目、已改措辞。
2. **`sd` 的说明是过期事实**：写着「必须 FAT16/FAT32 —— 这版没有 exFAT」，而 exFAT 2026-09-11 已经支持，
   判据也早改成 `fs ne none`。已改。
3. **`rtc` 的说明是过期事实**：写着「`clk=lsi` 说明时钟源是内部 RC」，而 RTC 2026-09-10 已换 LSE，
   判据是 `clk eq lse`。已改成「应当是外部晶振，读到内部 RC 说明晶振没起来」。

## 测试补了两条（H5）

| 断言 | 防的是什么 |
|---|---|
| `changing a parameter withdraws the verdict` | 改参数再按「开始测试」，结论不能是「失败」，且要说清为什么不给结论；点「恢复方案参数」之后又能判 |
| `no protocol words left on the cards` | 逐个端口扫卡片，命中 `BANNED_ON_CARDS` 里任何一个协议词就判失败 |

⚠️ **这个洞为什么一直没被发现**：H5 从来只按方案预填的参数按「开始测试」，
**没有任何一条断言改过参数**。

## 2026-09-11 补：四个一直没被点过的控件

用户问「你把所有的上位机软件上的端口和功能都测了么」，查出来**端口那一层测全了**（19 个端口逐个按过
「开始测试」），**功能这一层漏了四处**，一次都没被自动化点过：

| 控件 | 漏的原因 | 现在 |
|---|---|---|
| 「单独跑」单个 `pt.run` 目标 | 目标只通过「开始测试」间接跑过 | ✅ 用 `eth.link` 验：出结论 + 日志里确有 `pt.run eth.link` |
| 「自动回环应答」勾选框 | 只有 API 层被 Go 测试调过 | ✅ 开关各一次，状态字要跟着变 |
| 「绑上 / 解开」对端串口 | **模拟板自带对端**（`sim` 的 `stimulate()` 自己演所有 link 端口），所以模拟板上根本用不到它 | ⚠️ 只测到 UI 机制（实测真的开了本机 COM1 再解开）。**「绑对适配器才闭合链路」只有真工位能证明** |
| 方案页的「运行」按钮 | `/api/plan/run` 只被 Go 测试调过，**按钮没被按过** | ✅ 用 `bench-smoke.json` 在页面上跑完整一轮，7 步全部回判据 |
