# 补记录框架自己的洞

## Destination

**一件事做完了，有东西能证明它全做完了** —— 不是「每一步的判据都绿了」，
而是「该做的步骤本身没有漏」。

## Notes

**为什么开这张图**（2026-09-16，用户的诊断）：

> 「这是几个问题共同造成的结果：1 文档记录的分散，2 没有一个整体的规划或者整个任务的 todo。」

**证据就在上一张图里。** `把文档收编进 OpenPLC_Docs` 的终点写的是
「**三个**代码仓的 `docs/` 搬空」，`逐份定去向` 的判据写的是「表覆盖**三个仓**的全部 `.md`」。
那条判据跑出来 43/43、对称差为空 —— **它验得完美，验的却是一个写窄了的范围**：
实际是七个仓，而且文档路径还写在 43 个源文件的注释里。两批都是用户追问才发现的。

**机制**：每张票都有 `## 怎么算答完`，**但整张图没有「怎么算全做完」**，
所以终点本身的完整性没有任何东西去验。

规矩同 [../MAP-AND-TICKET-CONVENTION.md](../MAP-AND-TICKET-CONVENTION.md)，票号前缀 `FG-`。

## 全集

这张图的范围由这个决定，**关最后一张票之前重跑一遍对账**：

```
python tools/list_wayfinder_map_frontier.py --all  ＋  maps/*/map.md
```

这张图的范围是**本仓的每一张图和每一条检查**，所以全集就是它们自己。

## Decisions so far

- [一张图怎么算「全做完」](issues/FG-01-what-makes-a-map-done.md)：**全集必须是一条能重跑的命令**，按「找什么」写不按「在哪找」写；关票前重跑对账；检查强制每张图都有 `## 全集`

## Not yet specified

- **全集算不出来的那种图怎么办** —— `产线测试补齐` 的范围是一份外部文档的目录，重跑不了，机制退化成一句承诺
- 「分散」这一半已经消了（文档都在本仓），但**清点的起点从哪来**还没解决 ——
  这次的起点是「我们当时在看的那三个仓」，没有任何地方写着「这个产品有七个仓」是清点的全集

## Out of scope
