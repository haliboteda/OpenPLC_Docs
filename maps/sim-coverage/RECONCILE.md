# 0.1.3 的需求在模拟里测到哪一步 —— 全集对账

图：[0.1.3 在模拟环境里能测的都测掉](map.md)。2026-10-04 按地图的「全集」命令（M1–M3 全部需求）对账，用 `$PROD` 各模块文档里用例的「条件」列归类：
**有模拟用例** = 至少一条用例在 bootloader 替身或 Renode 上自动跑；**只有主机用例** = 只在 CTest 一类主机测试里；**只能上板 / 手工 / 静态** = 两者都没有，原因逐条写在最后一列。

「有模拟用例」**不等于不用上板**：替身和 Renode 证明的是代码的决定，真时序、真电平、真 flash 擦写仍要真板子，每条用例的「条件」列写明了。

## 只能上板 / 手工 / 静态（17）

| 需求 | 是什么 | 谁证明 | 为什么模拟里没有 |
|---|---|---|---|
| `R1-04` | 入口通道 | `T1-27` | 按住 BOOT0 复位进上传模式：手势要在 Renode 里跨复位驱动 BOOT0，没接；按键本身只能上板 |
| `R1-05` | 入口通道 | `T1-25` | CDC 模式不起以太网：替身每次冷启动清掉 SRAM4，带交接记录启动要给替身加开关，没接；CDC 本身只能上板 |
| `R1-06` | 入口通道 | P2（查不分叉，非本功能） | 只有静态检查（P2 查交接代码不分叉）；「只有一条通道」是代码结构的事实，不是运行时行为 |
| `R1-10` | 发现 | `T1-03` | 发现回复 2 s 内：替身的 PC 网络转接本身有秒级抖动，判不了板子 |
| `R1-11` | 发现 | `T1-04` | 10 分钟发现浸泡：要抓 lwIP / PHY 长跑问题，替身换掉了这一层 |
| `R1-13` | 发现 | 手工 | 手工：定位靠广播 + UID，要两块以上真板子在同一网段 |
| `R1-14` | 发现 | P2（查算法一致，非本功能）+ 2026-09-28 两块板实测不同，见 [ACCEPTANCE-CHECKLIST.md](../../docs/tables/ACCEPTANCE-CHECKLIST.md#chk-c--单板出厂) | MAC 互不相同：要多块真板子的 UID；P2 只查算法一致 |
| `R1-30` | 记录与诊断 | 手工 | 手工：复位原因要真的按复位键、断电、软件复位；Renode 的 RCC 在软件复位后仍报上电（SIM-02） |
| `R1-31` | 记录与诊断 | 手工 | 手工：VBAT 没电要真把电池拿掉 |
| `R1-32` | 记录与诊断 | 代码审查 | 代码审查：「每条拒绝路径都说得出原因」是对代码的逐条阅读，没有一条运行时用例能穷举 |
| `R1-33` | 启动切换 | `P15` ⁷ | 只有静态检查（P15 查链接结果的对齐），不是运行时行为 |
| `R1-34` | bootloader 自升级 | `T1-29` | `flashboot` 真写扇区 0：替身不落盘扇区 0 |
| `R3-01` | 交权前 | `T3-01` | SDRAM 自检失败时打根因：Renode 的 FMC 是桩，自检恒过，失败那支模拟不出 |
| `R3-02` | 交权那一刻 | 手工 | 手工：交权时外设冷不冷，要在真芯片上逐个外设看寄存器复位值 |
| `R3-04` | 引脚可见性 | P4 + P2（查表自洽与不分叉，非「不会误碰」） | 只有静态检查（P4 + P2）；「用户不会误碰」不是运行时行为 |
| `R3-05` | 串口不被抢 | `T3-03` | `Serial4.begin()` 不掐掉诊断口：原故障是引脚复用冲突，Renode 不建模复用 |
| `R3-07` | 网络不被 sketch 卡住 | 手工 | 手工：`delay()` 期间应答网络、能经网口上传；Renode 网口能通，但完整上传要 TAP 驱动（SIM-06 定不装） |

合计 58 条需求，全部归了类（2026-10-04 加了 `R3-14`）。
