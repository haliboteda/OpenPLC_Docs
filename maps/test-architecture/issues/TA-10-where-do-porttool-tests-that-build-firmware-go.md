# 依赖固件源码的 PortTool 测试归哪

Type: grilling
Opened: 2026-10-02
Status: resolved
Blocked by: -

## Question

PortTool 的 T4-01（协议契约）、T4-02 / T4-03（面板在浏览器里点一遍，对端是模拟板）、校准值区核对，都要编 `$BOOT` 里的工装固件源码 `TestCase/porttool/`。按决策 78 的判据它们要两个仓，归 `$TEST` 契约层；但工装固件和 PortTool 是同一个工装的两半，模拟板也是 PortTool 日常开发离不开的。是照判据搬去 `$TEST`，还是把「工装固件源码」算作 PortTool 的一部分、让这几项留在 `$PORTTOOL`，或者别的分法。

## 怎么算答完

T4-01、T4-02、T4-03、校准值区核对、模拟板各有唯一去处；如果不照判据走，把例外写进决策 78 并说明理由。

## Answer

2026-10-02 定（用户按推荐定）。工装算一个部件，源码分在两个仓：`$BOOT/TestCase/porttool/` 和它编译时用到的 `$BOOT` 头文件算 PortTool 的一部分，写进决策 78 的例外。

| 测试 | 去处 |
|---|---|
| T4-01（协议契约）、模拟板、T4-02（浏览器里点面板，对端模拟板） | `$PORTTOOL` 部件测试 |
| T4-03（Linux 版面板接真板子） | `$PORTTOOL`；要上真板子这一点按「只需要一个仓、但必须上真板子的测试归哪」统一处理 |
| 校准值区格式核对 | 和 P2 里 bootloader 对板卡包那一项合成一道，放 `$TEST` 契约层，一次比三方：`calib_area.h` 不属于工装固件，不在例外里 |

理由：PortTool 本来就要读工装固件源码（编工装镜像、打交付包），这条依赖去不掉；照判据把模拟板搬进 `$TEST` 会让部件仓反过来依赖测试仓。
