# KNX 库的 TP 收发怎么在本板上发出合法帧

Type: grilling
Opened: 2026-09-29
Status: resolved
Blocked by: -

## Question

`OpenPLC_KNX` 用 USART1（19200 8E1）驱动 STKNX，而 STKNX 是裸模拟收发器，位时序要 MCU 用定时器产生（TIM12_CH1 发、TIM1_CH3 收）；工装固件的 `porttool_knx.c` 用脉冲时序在真总线上收发过真帧。库的 TP 物理层是改成定时器驱动（照工装那套），还是先上板验证现有 UART 路径到底行不行；PB14 空闲为高会不会一直往总线上打脉冲。

## 怎么算答完

先在真板上用 ETS 看现有库发的帧（总线只接电源 + ETS），得出行 / 不行；不行就定下改法（移植哪部分、放在哪层），改完后 ETS 里能看到板子发的组报文、板子能打印 ETS 发来的报文。

## Answer

2026-10-03 定（用户：「有错误直接改，按照正确的做」）。不先上板测现有的库：按 STKNX 数据手册（DocID031327 Rev 1 §5.1）TP1 是 9600 bit/s、逻辑 0 为 35 µs 有源脉冲、空闲时 `KNX_TX` 为低，而库用 USART1 19200 8E1 驱动 PB14，UART 空闲为高等于一直往总线打脉冲，不可能对，接真总线测还会干扰总线。改法：新写一个 STKNX 数据链路层替换协议栈里的 `TpUartDataLinkLayer`（栈按 TP-UART 芯片的主机协议说话，而 STKNX 不是 TP-UART），用定时器按数据手册收发 TP1 位，自己组字节、帧、应答，位时序照搬工装固件里在真总线上验证过的 `porttool_knx.c`；上层协议栈不动。实施和 ETS 上板验收记在 `work/TODO.md`「KNX TP 收发改成定时器驱动」。

## 引出了什么新的未知

已发布的 0.1.3 里 KNX 库接在真总线上有害（一初始化就占总线）。新数据链路层是一大块新代码，上板验收前不进 0.1.3。
