# 撤销记录点名的是序号还是公钥

Type: grilling
Opened: 2026-09-19
Status: resolved
Blocked by: -

## Question

`'R'` 记录（撤销记录）的 64 字节载荷里放什么。三个候选，2026-09-19 摊开过：

| | 撤销点的是 | 要记住什么状态 | 记错 / 丢了会怎样 |
|---|---|---|---|
| **A** 只拉线 | `serial` 上的一条下限 | 线在哪（写在记录里，板子自己有） | — |
| **B3** 线 + 位图 | `serial` | ① 发到几号了（PC 上 `<key>.certserial`）<br>② 之前撤过谁（快照要带上） | ① 撞号 → **静默撤错人**<br>② 漏带 → **被撤的人复活** |
| **C** 按叶公钥 | 叶公钥前 N 字节 | **什么都不用记** | — |

各自的代价：

- **A**：每次撤销都连坐 —— 在职同事要重发证书，**而且板上正跑着的固件也会失效、必须重传**。治不了，是一刀切语义的固有后果
- **B3**：依赖 `serial` 唯一，而今天没有保证（`iapcert.go:179` 的计数器文件删了从 1 重来、私钥拷到第二台机器必然撞号、写回失败只打 warning）。工具侧只能治一半 —— **私钥搬了、状态文件没搬**这种情况治不了
- **C**：累加语义，**压缩回收不了**（每条记录带着不同的名字，没有被覆盖的历史可扔）；**撤了不能撤回**

用户 2026-09-19 的原话：**「听起来 C 不错」** —— 但没最终拍板。

要定四件事：

1. **选哪个形状**
2. 选 C 的话，**被撤公钥取前几个字节** —— 8 / 12 / 16，对应一条记录装 8 / 5 / 4 个人。P-256 公钥的 X 坐标本质均匀随机，64 位在一千把密钥下撞一次约 `5×10⁻¹⁵`
3. **撤销检查放哪** —— `iap_cert_verify()` 里（两个调用点自动覆盖，但会让这个纯函数依赖 `owner_slot`），还是放 `iap_auth.c:122` 和 `IAP_server.c:428` 两处
4. **`serial` 怎么精简** —— 选 C 之后它在板子侧完全没有作用了（`iap_cert_verify()` 只把它算进签名，从不比对；`iap_cert.h:41` 的注释原话是「Only meaningful once revocation exists」，而 C 不用号）：

| | 做什么 | 收益 | 代价 |
|---|---|---|---|
| ① 删字段 | 证书 132 → 128 字节，`IAP_CERT_SIGNED_LEN` 68 → 64 | 4 字节 | ⚠️ **破坏性**：已发出的证书全废；`iap_fw_metadata_t` 里存着整张证书，**所有已装板子的 app 下次启动被拒** |
| ② 保留字段、停止发号 | 删 `NextSerial()` / `CounterPath()` / `.certserial` 整套，一律写 `0xFFFFFFFF` | 工具侧少一整套状态管理，**「换电脑就撞号」整类问题消失** | 格式不变，向后兼容 |
| ③ 不动 | —— | 零 | 留一个没人用的字段，下一个人会以为它有意义 |

⚠️ **选 C 的话 `R4`（永不能撤到一个有效根都不剩）不再靠 `serial == 0xFFFFFFFF` 免检**，
改成「撤销项 == 当前生效的根公钥 → 忽略/拒收」。这条要一起写进答案。

## 怎么算答完

`M2-ownership.md` 里有一节写明四样东西，缺一不可：

- `'R'` 记录的**字段布局**（含载荷取几字节、一条装几个）
- 板子收到一张证书时的**判断顺序**，以及 `R4`（永不能撤到一个有效根都不剩）**具体靠哪一行代码落地**
- 另外两个形状**为什么没选**，各一句话
- **`serial` 的去向**：精简到第几层、理由一句话

并且 [要改的东西，一条不落](../CHANGE-LIST.md) 里标着 `⏳ 票 1` 的那些条目（A1–A6、A8、B1、B4、B6–B8、C1）都能从这个答案推出形状。

## Answer

2026-09-20 定。**方案 C：按叶公钥撤销，取前 16 字节，一条记录装 4 个。**

### 为什么是 C

**A 和 B3 都回答不了「客户换了电脑」**。两者都按 `serial` 点名，而 `serial` 的唯一性靠
`<根私钥>.certserial` 这个**必须跟着私钥一起搬的状态文件** —— 文件删了从 1 重来、私钥拷到
第二台机器必然撞号、写回失败只打 warning。**出错的样子是静默撤错人。**

C 点名的是**证书里自带的叶公钥**，不需要任何人维护任何状态。

另外两个没选的理由各一句：

- **A（只拉线）**：每次撤销都连坐 —— 在职同事要重发证书，**而且板上正跑着的固件也会失效、必须重传**。这是一刀切语义的固有后果，治不了
- **B3（线 + 位图）**：见上，依赖 `serial` 唯一

### 为什么是 16 字节

| 取几字节 | 一条装几个 | 定向碰撞 | 64 字节用满没 |
|---|---|---|---|
| 8 | 8 | 2⁶⁴ —— 有资源的攻击者够得着 | ✅ |
| 12 | 5 | 2⁹⁶ | ❌ 浪费 4 字节 |
| **16** | **4** | **2¹²⁸** | ✅ |

决定性的是 **C 不可逆** —— 撤了撤不回来，一次碰撞导致的误撤是**永久的**，除了换根没有补救。
为没有补救的失效多留余量值得。容量不是问题：**51 槽 × 4 = 204 人**。

### `'R'` 记录的字段布局

```
偏移  0    1    2      4          8      12                             76        92      156 160
     ┌────┬────┬──────┬──────────┬──────┬──────────────────────────────┬─────────┬────────┬───┐
     │'R' │ -- │ver=3 │generation│flags │ 4 × 16 字节被撤叶公钥前缀      │ uid[12] │prev_sig│rsv│
     └────┴────┴──────┴──────────┴──────┴──────────────────────────────┴─────────┴────────┴───┘
     └──────────── 签名覆盖前 88 字节，和 'O' 记录同一条规则 ─────────────┘
```

⚠️ 偏移 1 那个字节（原 `slots`）**随本轮「无效字段一律删」一起去掉**，并进 `reserved`。
布局其余部分和 `'O'` 记录完全对齐：同样 160 字节、同样带 `uid`、同样**必须被当前生效的根签名**，
**`'R'` 没有 TOFU 例外**（出厂态没有叶子要撤）。

未用满的槽位填 `0x00`，扫描时跳过全零项。

### 板子的判断顺序

```
收到一张证书
   ↓
取 cert.leaf_pubkey 的前 16 字节
   ↓
走链，每遇到一条生效的 'R' 记录，比对它的 4 个项
   ↓
命中 → 拒；走完没命中 → 放行
```

⚠️ **不在 RAM 里建集合。** 验证时直接扫 owner 区即可 —— 只有 51 条记录，而验证的频率很低
（每次启动一次、每次上传一次）。这样省掉一块变长的 RAM 缓冲，也省掉「集合放不下怎么办」这个问题。

### `R4`（永不能撤到一个有效根都不剩）怎么落地

**不再靠 `serial == 0xFFFFFFFF` 免检**（`serial` 已删）。改成：

> **一个撤销项如果等于当前生效的根公钥前 16 字节 → 忽略这一项**，并在启动日志里喊一声。

**忽略那一项，不是拒掉整条记录** —— 一条记录装 4 个人，拒整条会让另外 3 个也撤不掉。

### 撤销检查放哪：**给 `iap_cert_verify()` 加一个参数**

不放函数内部（会让这个纯函数依赖 `owner_slot`），也不靠约定让每个调用点自己记得加
（**漏掉一个 = 撤销静默失效**）。改签名，让**编译器**保证每个调用点都得显式处理 ——
今天的两个调用点是 `iap_auth.c:122`（会话认证）和 `IAP_server.c:428`（镜像验签），
将来新增第三个会编译不过。

### `serial` 的去向

**整个删掉**（2026-09-19 已定，见地图的 Decisions so far）。证书 132 → **128 字节**，
`IAP_CERT_SIGNED_LEN` 68 → **64**。C 点名的是公钥，那个「将来能被撤销点名」的编号不会来了。

## 引出了什么新的未知

**有一条，已进迷雾**：`'R'` 记录是**累加**语义（板子把所有 `'R'` 的项并起来），
所以新记录只写**新增**的那几个、不用重复旧的。但**工具要知道已经撤过谁**才能避免重复写 ——
它是从板子读回来，还是管理员自己记？这并进迷雾里原有的「工具侧 `revoke` 的交互」那条。
