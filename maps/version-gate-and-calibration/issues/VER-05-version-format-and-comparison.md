# 版本号的格式和比大小的规则

Type: grilling
Opened: 2026-09-21
Status: resolved
Blocked by: VER-01

## Question

`OPENPLC_APP_VERSION(1, 0, 0)` 收三个数，但「怎么算更旧」还没定。三件事：

**1 · 格式**：三段够不够？要不要 build 号？每段上限多少（今天 `boards.txt` 的注释要求「点分，每段 0-255」）？

**2 · 比大小**：逐段数值比较是默认答案，但要写死 —— 字符串比较会让 `"10.0.0" < "9.0.0"`。
预发布后缀（`1.0.0-rc1`）要不要支持？不支持的话，宏要不要在编译期拦住它？

**3 · 板子处于不同状态时怎么判**。identity 的 `role` 字段已经区分了是谁在报版本：

| 板子回的 role | 第 4 段是谁的版本 | 建议 |
|---|---|---|
| `CUSAPP` | **app 的版本** | 正常比对 |
| `BOOTLD-INVALID` | bootloader 的版本 | app 本来就无效，**没有「当前版本」可言 → 放行** |
| `BOOTLD` | bootloader 的版本 | 取不到上一个 app 的版本 → **建议放行**（走到这一步通常是上次升级出了问题，拦住反而坏事） |

⚠️ **上面那一栏是 2026-09-21 对话里的建议，用户没有逐条拍板**，本票要把它定死。

**4 · 比对必须发生在什么时候**：板子一旦被请进 bootloader 就报不出 app 版本了，
所以**比对要在「请它进 bootloader 之前」那次发现里做**。这条是约束，不是选项。

## 怎么算答完

1. 写出版本号的**字段、位宽、上限**，以及宏要加的编译期检查
2. 写出**比大小的规则**，包括「相等」怎么处理（拒绝？放行？）
3. 把上面那张 role 表**逐行定死**，每行给一句理由
4. 写明比对在上传流程的**哪一步**发生，以及那时板子处于什么状态
5. 写明**拿不到板子版本时**（发现超时、板子不应答）默认放行还是拒绝

## Answer

2026-09-21 定（六条一次拍板）

| | 结论 | 理由 |
|---|---|---|
| **格式** | **三段 `major.minor.patch`，每段 0–255** | 和 `boards.txt` 现有的「点分，每段 0-255」一致。**不加 build 号** —— 每次编译都变的东西用户改不动，也没法比 |
| **比大小** | **逐段数值比较**，严格小于才算「更旧」 | 字符串比会让 `10.0.0 < 9.0.0` |
| **版本相等** | **放行** | 重烧同一版是日常操作（改了配置、换了板子），拦住会很烦 |
| **预发布后缀** | **不支持**，宏在编译期拦掉 | 支持了就要定「`rc1` 和正式版谁大」，那没有标准答案 |
| **发现超时 / 板子不应答** | **拒绝**，提示「拿不到板子版本」 | 和「板子明确说自己没版本」不是一回事：后者是已知，前者是未知，**未知不该默认放行** |

### role 逐行定死

| 板子回的 role | 第 5 段是什么 | 怎么做 | 为什么 |
|---|---|---|---|
| `CUSAPP` | app 的版本 | **比对** | 唯一能拿到「板子现在跑的是哪一版」的状态 |
| `BOOTLD-INVALID` | `-` | **放行** | app 本来就无效，没有「当前版本」可言 |
| `BOOTLD` | `-` | **放行** | 走到这一步通常是上次升级出了问题，这时候拦住反而坏事 |

### 比对发生在哪一步（这是约束，不是选项）

**必须在「请板子进 bootloader 之前」那次发现里做。** 板子一旦进了 bootloader，
它报的第 5 段就是 `-`，拿不到上一个 app 的版本了。

### 怎么拦掉非法版本号

宏里加编译期断言，顺带把「三个参数必须是 0–255 的整数常量」一起拦住：

```c
#define OPENPLC_APP_VERSION(maj, min, pat)                                    \
    _Static_assert((maj) >= 0 && (maj) <= 255, "version field out of range"); \
    _Static_assert((min) >= 0 && (min) <= 255, "version field out of range"); \
    _Static_assert((pat) >= 0 && (pat) <= 255, "version field out of range"); \
    extern "C" const char openplc_app_version[] = #maj "." #min "." #pat
```

传 `"1.0.0-rc1"` 这种非整数常量表达式**在断言那一行就编译失败**，不需要额外的解析。
