# 旧编号 → 新编号 完整对照

**54 条需求逐条落位的结果，一条不少。** 由[54 条需求逐条归模块](issues/DR-02-assign-requirements-to-modules.md)
那张票产生，用户 2026-09-17 逐条拍板。

> ⚠️ **这份表是映射，不是需求的家。** 「要做到什么」那一列是从
> [../../docs/tables/STATUS.md](../../docs/tables/STATUS.md) 逐字抄的，**抄是为了能对照**，
> 不是第二份出处。实施时需求搬进模块文档，这份表只留编号对应关系。
> `ID-MIGRATION.md` 直接由它生成。

**判据**（建图时定，逐条套用）：**「这条没做到，外面的人就失去了让板子做某件事的能力」**。
答得出失去什么能力的进模块；答不出的进工程约束。

## M1 · 固件升级（32 条）

**排序**：按一次升级实际走过的阶段 —— 入口通道 → 发现 → 会话 → 认证 → 传输与校验 → 启动切换 → 记录与诊断。
**不按旧字母顺序**，所以 `B11`（UID 定位）和 `E1`（MAC 唯一）落在「发现」段里，
`C1`–`C5` 被拆进「认证」「传输与校验」「启动切换」三段。

## 工程约束（9 条，不进功能表）

**这一层回答的是「我们怎么保证板子一直做得到」，不是「板子能做什么」。**
不做到板子功能不变，但我们会失去发现它坏掉的能力。

**排序**：构建产物 → 版本与跨仓一致 → 检查工具 → 交付流程。

| 新编号 | 旧编号 | 守什么 | 要做到什么 | 状态 |
|---|---|---|---|---|
| **ENG-01** | `E3` | 构建产物 | bootloader 镜像装得进为它保留的 flash | ✅ |
| **ENG-02** | `D7` | 版本一致 | bootloader 自报版本与 core、发布说明一致 | ✅ |
| **ENG-03** | `D8` | 跨仓不分叉 | 跨仓镜像的代码不会静默分叉 | ✅ |
| **ENG-04** | `D9` | 跨仓不分叉 | `$CORE_LIVE` 验证过的改动确实进了 git | ✅ |
| **ENG-05** | `F1` | 检查工具 | 改完代码有一条命令能跑完所有不需要板子的检查 | ✅ |
| **ENG-06** | `F5` | 检查工具 | 全套自动化测试脚本用 Python 写，不需要 PowerShell | ✅ |
| **ENG-07** | `F3` | 交付流程 | 发版前有验收单，且能抓住捆绑升级风险 | ✅ |
| **ENG-08** | `F4` | 交付流程 | bootloader 与 app 必须捆绑升级这条风险写进了发布说明 | ✅ |
| **ENG-09** | `F2` | 交付流程 | 每块出厂板有逐板检查单 | 🟡 |

## 不进功能表：进 DEFERRED-DESIGNS（2 条）

M1 和 M2 的「边界」一节写指针指过去，不在功能表里留 ⛔ 行。

| 旧编号 | 要做到什么 | 状态 | 为什么不做 |
|---|---|---|---|
| `C13` | 产线给每块板发唯一密钥，取代固定密码 | ⛔ | 2026-09-04 定：不需要做。会话认证改走证书，板子里从此不存共享密钥 |
| `C14` | flash 写保护（WRP）禁止 app 写 bootloader 区 | ⛔ | 2026-09-04 定：厂商不上，留给客户按需操作。设置后清除要 ST-Link 物理访问 |
