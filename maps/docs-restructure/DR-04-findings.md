## 3. 图和 markdown 文字对不上的地方 ⭐

[OWNERSHIP.md:3](../../docs/modules/M2-ownership.md) 写着「⚠️ 和本文打架时以本文为准」。
**核对下来确实打架了，而且有一条是 OWNERSHIP.md 自己错。**
以下每条都回到了源头核实 —— bootloader 仓库 `$BOOT/IAPServer/` 的代码，不是任何抄件。

### ❗ 分歧 1（最重）：`generation` 的胜出规则，OWNERSHIP.md 写反了

| | 说的是 |
|---|---|
| **OWNERSHIP.md:202**（记录格式表 offset 4） | `generation 单调递增，**最大的那条有效记录获胜**` |
| **参8**（`security-design.html:1650`） | 整张图的上半部**专门用来否掉这条规则**：「❌ 如果按『代号最大的那条有效记录胜』…… 任何能往那片区域追加字节的人，只要写一条代号很大、prev_sig 全 0 的记录，就夺权成功」 |
| **源头：`$BOOT/IAPServer/owner_slot.c` `resolve_chain()` 头注释** | 原文 `Records are walked oldest first, never "highest generation wins". That shortcut would be a hole` |
| **OWNERSHIP.md:82**（同一份文档的状态机 ASCII） | 「沿链取最后一条有效的作为根」—— **和 :202 自相矛盾** |

> ✅ **结论**：**图对，OWNERSHIP.md:202 那一行错**，而且 OWNERSHIP.md 内部就自相矛盾
> （:82 对、:202 错）。这不是措辞差异 —— `:202` 描述的正是代码注释里写明「会开一个洞」
> 的那条规则。转图时以参 8 和代码为准；`:202` 那行要改成「必须沿链逐条走，
> 一条不过就停」，**但那属于后续执行，本票不动**。

### ❗ 分歧 2：证书大小，OWNERSHIP.md 写成了 owner 记录的大小

| | 说的是 |
|---|---|
| **OWNERSHIP.md:37** | 「简单模式那张自签证书……纯粹是 **160 字节** + 一次验签」 |
| **HTML 全篇**（场景索引表 `:208`、参1 `:753`、参7 `:1528`） | 一律 **132 字节** |
| **源头：`$BOOT/IAPServer/iap_cert.h:33`** | `#define IAP_CERT_SIZE 132U`，并有 `_Static_assert(sizeof(iap_cert_t) == IAP_CERT_SIZE, ...)` |

**160 字节是 `OWNER_RECORD_SIZE`**（`$BOOT/IAPServer/owner_slot.h:38`），不是证书。

> ✅ **结论**：**图对，markdown 错**，是抄串了相邻章节的数字。

### ❗ 分歧 3（方向相反：图自己过期了）：参7 指着一个已经修好的漂移

参7（`security-design.html:1520` 附近的红字块）写着：

> ⚠ 文档漂移：`$PROD/docs/modules/M1/JOURNAL.md` 的类型表说 8 格，但上电扫描树和写入流程图仍写着
> 「'M'（4格）」「剩余格子 < 4」「追加 M 记录（4格）」……那三处该改，不在本次范围。

实测 [../../docs/modules/M1/JOURNAL.md](../../docs/modules/M1/JOURNAL.md)：`:24` `:29` `:59` `:115` `:123`
**五处全部是 8 格，一处 4 格都没有**。

> ✅ **结论**：**那条漂移已经被修掉了，图上的指责本身成了过期内容。**
> 转图时这一整块要**删掉**，不要原样抄进模块文档 —— 抄过去等于凭空造一条假缺陷。

### ❗ 分歧 4（图错）：参8 的「三条回落」里有一条代码做不到

参8 底部「`owner_slot_root()` 的三条回落」写：槽从没写过 / 链尾是 cleared / **链在中途断了** —— 三种都回落到 `fw_public_key`。

源头 `$BOOT/IAPServer/owner_slot.c` 的 `owner_slot_root()` 只有两个回落条件：
`s_effective == NULL`，或生效记录带 `OWNER_FLAG_CLEARED`。
而 `resolve_chain()` 断链时是 `s_effective = current`（断点**之前**最后一条有效记录），
不是 `NULL`。所以：

- 链在**第一条**就断 → `s_effective == NULL` → 回落 ✅
- 链在**第二条及以后**断 → 用断点前那条记录的根，**不回落** ❌

> ✅ **结论**：**markdown 对，图错。** [OWNERSHIP.md:74-87](../../docs/modules/M2-ownership.md)
> 「状态机」那张 ASCII 只写了两条回落，反而和代码一致。转图时这条要么删，
> 要么改成「链在**第一条**就断」。

### ⚠️ 分歧 5（例子编号对不上，不是事实错）

[OWNERSHIP.md:144-152](../../docs/modules/M2-ownership.md) 的「三个操作」表：
① `takeown` 追加 **G1**；② 换 owner 追加 **G3**，必须被 **G2** 签名。
参8 画的链是 G1（认领）→ G2（换主人）→ G3（再换）。

两处单看都对（都是举例），但并排读会让人以为 takeown 之后直接跳到 G3。
转图时统一写成「G(n+1) 必须被 G(n) 签」。

### ⚠️ 措辞层面（记下来，不建议单独开票）

`OWNERSHIP.md:108` 说告警的代价是「32 字节常量 + 启动时一次 **64 字节的哈希比对**」。
实际是：对 64 字节的根公钥算 SHA-256，再比 **32 字节**摘要
（`$BOOT/IAPServer/owner_slot.c` 的 `k_published_root_sha256[32]`）。
图（参2 `:827`）写的是「存了一份公开根的 SHA-256 常量，启动时比对当前信任的根」，更准。

### 没有发现分歧的地方（核对过，明写出来）

以下都逐条比对过，**图和 markdown 一致**，不需要在转图时做取舍：

- 出厂根私钥必然公开的那条推理链（OWNERSHIP.md:11「一切的起点」vs 参2 起点 ①）
- 告警触发条件是「当前根 == 公开根」而不是「槽空」（OWNERSHIP.md:89「告警的触发条件」vs 参2「为什么 ② 不会被告警」，代码 `report_root_trust()` 佐证）
- owner 区选址三选一的比较表（OWNERSHIP.md:41「为什么是这里」vs 参6）
- `RESERVED_TAIL_SECTORS` 那颗地雷（OWNERSHIP.md:70 vs 参6，图里还反链回了 OWNERSHIP.md）
- R1–R4 四条规则的挡住 / 挡不住（[OWNERSHIP.md:156-163](../../docs/modules/M2-ownership.md)「规则」vs 参12）
- 抄了谁 / 避开了谁（OWNERSHIP.md:256「借鉴与避坑」vs 参12：UEFI / Android Verified Boot / Chromebook / ESP32 aggressive revoke）
- WRP 厂商不上、C12 不做（**C12 = 「撤销叶子证书，且永不能撤到一个有效根都不剩」，状态 ⬜ 等真实需求，定义在 [../../docs/tables/STATUS.md:132](../../docs/tables/STATUS.md)**；OWNERSHIP.md:270「定下来的取舍」vs 参12）
- 撤销状态不放 RTC 备份域、DR2 撞过车（OWNERSHIP.md:187 + CHALLENGE-AUTH.md vs 参6 / 参9）
- 「板子上不存任何秘密」（KEYS.md vs 参1 / 参3）

## 4. 图上有、三份 markdown 里一个字都没有的事实

**这些不是分歧，是缺口。** HTML 一删就没了 —— 转图时必须显式落进模块文档，
否则会静默丢失。逐条核对过三份 md 全文，确认确实没有。

| 事实 | 图里在哪 | 该进哪 |
|---|---|---|
| nonce 的 **TTL 30 秒** | 流程 A ② · 参2 · 参9 | CHALLENGE-AUTH.md 通篇没有 TTL 这个概念，只说「一次性消费」→ M1 |
| **全局单 nonce**：CDC 和以太网并发请求挑战会互相冲掉，**是可用性怪癖不是安全洞** | 参4 · 参9（均注 `SECURITY.md:127-136`） | CHALLENGE-AUTH.md 没有 → M1 |
