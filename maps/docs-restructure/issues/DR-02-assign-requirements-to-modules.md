# 54 条需求逐条归模块

Type: grilling
Opened: 2026-09-17
Status: resolved
Blocked by: -

## Question

`STATUS.md` 第三节的 54 条需求要逐条落到 M1–M4 或者工程约束里，**一条都不许悬着**。
判据是建图时定的那一句：**「这条没做到，外面的人就失去了让板子做某件事的能力」**。

2026-09-17 建图时已经过了一遍粗分（写在这里是为了让这张票有起点，**不是结论**）：

| 模块 | 粗分进来的 |
|---|---|
| M1 固件升级 | A1–A7、B1–B11、C1–C5、C8、C9、D1、D2、D3、D5、D6、E1、E8 |
| M2 归属与信任 | C7、C10、C11、C12（C13/C14 已作废） |
| M3 应用运行环境 | D4、E2、E4、E5、E6、E7 |
| M4 产线工装 | F6 |
| 工程约束（不给号） | D7、D8、D9、E3、F1、F2、F3、F4、F5 |

**已知有争议、必须用户拍板的**：

- **E1（每块板 MAC 互不相同）** —— 是 M1 的一部分（网络发现靠它），
  还是硬件事实（跟着 UID 派生算法走）？
- **D3（复位原因）D5（RTC 备份域失效）** —— 它们服务的是「排查板子为什么停在 bootloader」的人。
  归 M1，还是该有一类「板子健康自报」？建图时按 M1 放的，**没验证过**
- **F2（逐板检查单）** —— 粗分放进工程约束，但它也可能属于 M4 产线工装
- **C13、C14 两条已作废的** —— 新文档里还留不留，留的话放哪
- **ID-MAP 写 53 条、实际数出 54 条** —— F6 是后加的没登记，确认一下还有没有别的没登记

⚠️ **归模块的同时就定了编号**：模块号是需求号和测试号的第一位，
所以这张票关掉之前不要开始改任何编号。

## 怎么算答完

`STATUS.md` 里的每一条需求都写明了它归哪个模块（或归工程约束），**没有一条悬着**，
争议的四类全部由用户拍过板。产出一份「旧号 → 模块」的完整对照，
后面 `ID-MIGRATION.md` 直接由它生成。

## Answer

2026-09-17 定。完整对照在 [../DR-02-id-mapping.md](../DR-02-id-mapping.md)，54 行一条不少。

**54 条全部落位，没有一条悬着。** 对账方式：从 `docs/tables/STATUS.md` 抽出所有需求号，
和对照表的旧编号列取差集，两个方向都是空。

| 去处 | 条数 |
|---|---|
| M1 固件升级 | 32 |
| M2 归属与信任 | 4 |
| M3 应用运行环境 | 6 |
| M4 产线工装 | 1 |
| 工程约束（`ENG-01`–`ENG-09`，不进功能表） | 9 |
| DEFERRED-DESIGNS | 2 |

**用户逐条拍板的五处争议**：

- **`E1`（每块板 MAC 互不相同）归 M1** —— MAC 撞了，量产时同网段大面积 IP 冲突，
  **以太网升级整条路挂掉**。判据问的是失去什么能力，不是谁实现的
- **`D3`（复位原因）`D5`（RTC 备份域失效）归 M1** —— 它们不是能独立做的一件事，
  是 M1 失败时用来看原因的。⚠️ **不是因为「只有两条不值得开模块」** ——
  条数不是判据，「是不是一件能独立发生的事」才是
- **`F2`（逐板出厂检查单）归工程约束** —— 那七项（`CHK-C1`–`C7`）**一条都没用到工装**，
  而且它是人要做的动作，不是板子的能力
- **`C13`（产线发唯一密钥）`C14`（WRP）不进功能表**，进 `DEFERRED-DESIGNS.md`。
  「为什么不上 WRP」会被反复问，M1/M2 的边界一节写指针指过去
- **`K` 族七个用例跨两个模块**：`K1` `K2` `K3` `K7`（工具传输前预判密钥）→ M1；
  `K4` `K5` `K6`（证书链）→ M2。**按每个 case 实际测什么分，不按三份文档现在怎么写分** ——
  那三份说了三套，而代码里根本没有这个映射

**M2 保持独立**（不并进 M1）：认领、换 owner、按住 BOOT0 十秒恢复出厂，
**这三件事一次固件都不用升**，是能独立发生的事。

**新编号的排法**（每组在对照表里都写明了）：M1 按一次升级走过的阶段排、
M2 按信任根的生命周期排、M3 按 app 拿到板子的时间顺序排、工程约束按守什么排。
**都不按旧字母顺序** —— 所以 `B11` 和 `E1` 落在 M1 的「发现」段里，`C1`–`C5` 被拆进三段。

顺带修掉 `docs/tables/ID-MAP.md` 的一个事实错误：它写需求 53 条、范围到 `F5`，
实际 54 条、到 `F6`（`F6` 是后加的没登记）。

## 引出了什么新的未知

   它是第七个符号，没有定义，读的人不知道它和 🟡 差在哪

   那是「Go 里写死的 13 个用例号怎么改」那张票，它被这张票挡着，**现在解锁了**
