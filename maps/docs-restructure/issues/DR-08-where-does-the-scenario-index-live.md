# 那张「场景索引表」住哪

Type: grilling
Opened: 2026-09-17
Status: resolved
Blocked by: -

## Question

`docs/modules/M2-ownership.md` 开头有一张**按用户处境组织**的索引：
八个处境（「我的板子起不来」「我要把板子交给客户」……）→ 该看哪张图 / 分支点 / 终点。

**它是整份文档里唯一按「读的人处在什么情况」组织的东西**，横跨 M1 固件升级和 M2 归属与信任。

**按模块划分的体系里没有任何一个模块容得下它** —— 这是这个划分标准撞上的第一个真实反例。
放进 M1 会漏掉 M2 的处境，反之亦然；拆成两半就不再是一张索引。

要定的是：模块化之后还要不要这样一张表；要的话它住哪一层
（入口文件？单独一份？还是别的形态）。

⚠️ **这件事不解决，那张表会在删 HTML 时静默消失** ——
`DR-06` 已经证明有 10 条事实只活在那份 HTML 里，这张表是第 11 件。

## 怎么算答完

要么这张表在新体系里有一个明确的家且已写明，
要么明确决定不要它**并写下为什么**（不能默认消失）。

## Answer

2026-09-17 定。**这张表放进入口文件**（那份总功能表 + 模块索引）。

它回答的是「从哪儿进」，入口文件正是回答这个的地方；它横跨 M1 固件升级和 M2 归属与信任，
任何单个模块文档都容不下，而入口文件本来就在所有模块之上。

**形态不变**：仍然是「八个用户处境 → 该看哪张图 / 分支点 / 终点」这张表，
只是终点列从 HTML 的锚点改成指向模块文档的链接。

⚠️ **这条决定的价值在「不让它默认消失」**，不在放哪一层 ——
`DR-06` 查明有 10 条事实只活在 `security-design.html` 里，这张表是第 11 件，
转图删 HTML 之前它必须已经有家。

## 引出了什么新的未知

**成立，而且比「没人定义过」更具体：入口文件要装的东西正在累积，但它和 `STATUS.md`
保留的那 12 行汇总撞车了，没有人判过。**

现在已经派给入口文件的：

| 派给它的 | 谁派的 |
|---|---|
| 总功能表 + 模块索引 | 这张图的终点（`map.md` 的 Destination 与 Notes） |
| 场景索引表（八个用户处境） | 本票 |

而 [docs 下 32 份文件逐份定去处](DR-05-where-does-each-doc-file-go.md) 判的是
**`STATUS.md` 只留第一节「全局，一眼看完」那 12 行汇总**，理由是「今天能干什么、
什么在挡路」跨所有模块。

**两者都在回答「一眼看完做到哪了」。** 按用户 2026-09-17 定的验收口径
（不要重复、不要把同一件事分多处记载），这是同一件事的两处记载，必须并掉一处 ——
但没有任何一张票判过并哪处。

另外，入口文件的**文件名和路径**至今没有任何地方写过，
`map.md` 只说「一个入口」，没说它叫什么、放在 `docs/` 的哪一层。
