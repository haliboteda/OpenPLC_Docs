# 换主之后，旧根签的固件还能不能启动

Type: grilling
Opened: 2026-09-20
Status: open
Blocked by: -

## Question

撤销（`revoke`）已经定成**只管未来** —— 被撤的叶签的固件照常运行，那把叶再上传才被拒。

**换主（`setowner`）要不要跟着改成同一个语义？**

今天两者是同一段代码的两个后果（`IAP_server.c:620-621`）：启动时拿 `meta.cert` 去验，
`root_sig` 对**当前**的 `owner_slot_root()` 验不过就拒。所以换一次根，旧根签发的所有固件
下次上电全部被拒、停在 bootloader 等重传。

两条语义可以不一致，但要想清楚代价：

| | 换主仍作废已装固件（今天） | 换主也只管未来 |
|---|---|---|
| 换主的即时代价 | 现场每块板下次上电都停机，要逐块重传 | 零，板子照常跑 |
| 板子转手给新主人 | 旧主人的固件**立刻失效** | 旧主人的固件**继续运行**，直到新主人主动重传 |
| header 要存什么 | 整张 `cert`（128 B），启动时对当前根验 `root_sig` | 整张 `cert` **加上安装时那把根**（多 64 B），或者别的锚法 |

⚠️ **这条直接决定 header 布局**，所以 [header 那一千多字节里放什么](HDR-05-what-goes-in-the-header.md) 被它挡着。

⚠️ **注意它和撤销不是同一个问题**：撤销针对「这个人不再被信任」，换主针对「这块板换主人了」。
`M2-ownership.md` 把换主类比成 UEFI 的改 PK —— 那是所有权移交，**新主人多半不希望前任的固件继续跑**。

## 怎么算答完

三件事都写下来才算：

1. 换主之后旧根签的固件**能不能启动**，一句话定论
2. 如果「不能」（保持今天的行为）：header 里靠什么判定，且**说明它和「撤销只管未来」为什么可以不一致**
3. 如果「能」（改成只管未来）：**点名哪几条用例要重写判据** —— 至少要核对 `T2-03`（换 owner：现任签名才算数）和
   [`$TOOL/TestCase/tools/run_claim_invalidates_existing_app.py`](../../../../IAPTranfer_Tool/TestCase/tools/run_claim_invalidates_existing_app.py)
   这个脚本（它的名字就写着「认领会作废已装 app」）
