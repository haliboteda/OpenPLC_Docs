# 每个端口有哪些测试项、判据和标准值从哪来

Type: grilling
Opened: 2026-10-09
Status: resolved
Blocked by: STG-02

## Question

每个端口有哪些测试项，各自在哪些测试类型里出现，判据的数值是多少？测试项取代原先的「基本 / 满载 / 负载」档位名：面板上要能看出每一项测了什么。

### 已定的测试项（用户 2026-10-09 / 10）

研发测试列出全部测试项；功能、老化、用户级功能测试从里面选（决策 97）。「只测一次」的项不随时长重复。

| 端口 | 测试项 | 只在研发测试 |
|---|---|---|
| ETH | 链路检查（只测一次）；数据收发：满速率回送，一次得出速率、丢包率、延时（决策 98） | — |
| USB | 枚举信息（只测一次）；数据收发，同 ETH | — |
| SD | 识别卡（只测一次）；读写：写入读回比对，同时记读写速度 | — |
| SDRAM | 总线检查（只测一次）；全片扫描（64 MB，四种图案） | 窗口 CRC（已去掉，[决策 141](../../../docs/tables/DECISIONS.md)） |
| DI | 逐路读电平（标准机 DO 驱动） | 正交计数 |
| AI | 每路一项读数：多点读，用板子上的校准公式换算后算偏差。点数 3–5 可设，标准值来自标准机、人工或专业设备（预留）；档位登记见决策 98 | 每路一项校准：人工逐点给标准值、填进面板，拟合出 k、b，存本地文件，再手动烧进板子（决策 97） |
| AO | 同 AI（读数换成输出，人工填仪表读数）；老化另有带负载输出（两路同出一个值，卡片上必填、没有默认，单位按 AO 档位：电流档 mA、电压档 mV，[决策 106、129、134](../../../docs/tables/DECISIONS.md)） | 同 AI 的校准 |
| RS232 | 与上位机收发，波特率可设（决策 98） | — |
| RS485 | 与上位机收发，同 RS232 | 收发切换脚自检（分清「没接对端」和「脚坏了」） |
| CAN | 对发，对端可选标准机或上位机（决策 98） | 控制器内部回环、外部回环 |
| KNX | — | 总线电源、回环收发、收整帧 |
| DO | 带负载输出：8 路可选，对端可选人工（人输入标准值）、标准机（标准机读取判定）、专业设备（预留） | 方波输出 |
| 继电器 | 每种测试都由人填总开合次数和间隔（决策 123） | — |
| 温度 | 两路读数 | — |
| 复位键、LED | — | 都只在研发测试；LED（板上只有 PE2 一个）可以长期 |

RTC 不是测试项：控制口连上后，连接区每秒显示一次板子时间。

### 每个测试项的对端和标准值来源

| 端口 · 测试项 | 对端 | 标准值从哪来 |
|---|---|---|
| ETH 链路检查、数据收发 | 电脑网口 | 链路：PHY ID `0x0007C131`、100 Mbit/s 全双工（现有方案 `station6-poweron.json` 的 `eth-link`） |
| USB 枚举信息、数据收发 | 电脑 USB | 枚举：`state=cfg`（同上 `usb-link`） |
| SD、SDRAM、温度、复位键、LED | 无 | 板子自己报 |
| DI 逐路读电平 | 标准机 DO1–8（STG-02 第 1 行） | 标准机给的电平 |
| DO 带负载输出 | 标准机 DI1–8（第 2 行）；或人工万用表 | 被测板命令的电平 |
| AI2 读数 | 标准机 AO（第 3 行）；或人工 / 仪器 | 标准机输出值或人工填的值 |
| AI1 读数 | 人工 / 仪器（STG-02 第 4 行） | 人工填的值 |
| AO 读数 | 标准机 AI1、AI2（电流档）同时读，或人工万用表（STG-02 第 5 行） | 人工填的仪表读数 |
| RS232、RS485 | 上位机 USB-232 / USB-485 转换器 | 上位机发出的数据 |
| CAN 对发 | 标准机 CAN（第 6 行）或上位机 USB-CAN | 对端发出的数据 |
| KNX（只在研发测试） | KNX 总线电源 / 测试盒 | 总线上的帧 |
| 继电器 | 触点上的负载，由标准机 / 专业设备读反馈；研发里也可人工数（[决策 130](../../../docs/tables/DECISIONS.md)） | 设定的开合次数 |

### 判据数值

| 项 | 判据 | 出处 |
|---|---|---|
| ETH / USB 丢包率 | 0 | 现有方案 `miss` 判 `count_zero`；决策 92 判丢包率 |
| ETH / USB 延时 | 只记录不判 | 决策 92「尽量保留」，没有给门限 |
| ETH / USB 速率下限 | 见下面对比表 | 无依据：满速率回送（TODO-fixture 第 35 条）还没做，没有实测值 |
| DO 带负载（标准机读） | 标准机 DI 读到的电平 = 被测板命令的电平，逐路 | 标准机 DI 只给 0 / 1，判不了电压 |
| DO 带负载（人工万用表） | 输出电压 ≥ 24 V 供电实测值 − 1 V | 无依据，建议值：VNQ5160K-E 导通压降在额定电流下远小于 1 V（压降值未对数据手册核实）；用相对供电的差值，因为 24 V 供电本身会浮动 |
| 温度两路 | 0–60 °C | 现有方案 `temperature` 步（relaxed 版 −10–80 °C）；LM50 换算见 HARDWARE-FACTS「两路板载温度」 |
| DO 方波（研发测试） | blink 模式：标准机 DI 在测试窗口内数到的翻转次数和期望次数相差 ≤ 1；PWM（1–2000 Hz）只记固件报的实际 `freq`，频率偏差靠示波器人工看 | 无依据，建议值：板上没有 DO 回读，标准机 DI 是唯一能自动数翻转的对端；PWM 频率远高于 DI 会话的采样周期（≥ 50 ms，PORTTOOL-FLOW） |
| DI | 见下面对比表 | — |

### ETH / USB 速率下限

TODO-fixture 第 35 条（满速率回送）做完后，在几块良品上实测，取最低值 × 0.8 写进方案文件（决策 44：限值在方案文件里）。现在不拍数。

### DI

只比 0 / 1：标准机 DO 逐路单独置 1、走 8 拍，每拍被测板只能有对应那一位为 1。能查出相邻两路短路，现有方案的全 1（`0xFF`）查不出；标准机 DO 只给 0 V / 24 V，量不了翻转电平。

### 无依据的建议值

DO 人工测量的「≥ 供电 − 1 V」和方波的「翻转次数差 ≤ 1」先采用，上板实测后再改。
