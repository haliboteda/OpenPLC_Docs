# 8,611 行怎么读完而不是抽样

Type: task
Opened: 2026-09-16
Status: resolved
Blocked by: DFC-01

## Question

人逐行读 227 个文件不现实；全自动提取分不出「为什么这么设计」和「这一行在干什么」。

要定一个**能走完全集**的做法：分批的切法（按仓？按域？按注释密度？）、
顺序、每批多大、谁判、怎么记录「这一批过了」。

⚠️ **不要做成抽样。** 上一张图就是因为范围写窄而漏掉两批，
这张图的锚是 [CORPUS.md](../CORPUS.md) 的 227 行，**少一个文件都不算完**。

⚠️ **2026-09-16 由 `DFC-01` 带出来**：判据的单位是**段**不是文件，而生成的代码和我们写的
混在同一个文件里（`ethernetif.c` 就是）。所以这张票要先定**锚是文件还是段** ——
`CORPUS.md` 现在按文件计 227 个。

## 怎么算答完


跑完之后，拿 `CORPUS.md` 逐文件对：**每一个文件都有一条记录说它处理过了**
（搬了什么 / 什么都没搬，两种都要有记录）。对不上的文件数必须是 0。
## Answer

2026-09-16 定。**锚是文件，覆盖记录由脚本生成，不是人手写的。**

产物：[../COVERAGE.md](../COVERAGE.md) —— **227 个文件每个一行**，
和 [../CORPUS.md](../CORPUS.md) 逐文件对账，**差 0**。

### 做法

| | |
|---|---|
| **分批** | 按问题域切五批，用户 2026-09-16 定的顺序：`boot` → `security` → 其余汇总 |
| **批 1、2 逐文件过** | 12 / 12 和 35 / 35，逐条记在 [../BATCH-LEDGER.md](../BATCH-LEDGER.md) |
| **批 3–5 汇总** | 用户当天定：「提取出来总结放在测试设计文档里面」。180 个文件按设计理由信号筛出 482 段，归并成 `docs/engineering/TEST-DESIGN.md` |
| **覆盖记录** | **脚本对着 `CORPUS.md` 逐文件跑一遍生成**，所以不可能漏掉语料里的文件 |

**「0 段」不是「没处理」，是「查过，没有可搬的」。** 两种都要有记录 ——
否则分不出「查过」和「忘了」，那正是这张票要防的。

### 锚是文件还是段

**锚是文件，单位是段。** 两者不冲突：
`CORPUS.md` 的 227 行决定「有没有漏文件」，`COVERAGE.md` 的段数说明「那个文件里有多少可搬的」。
`DFC-01` 定的三分判据作用在段上，但**完整性只能按文件对账** —— 段数是算出来的，不是清单。

### 验证

判据是「每一个文件都有一条记录（搬了什么 / 什么都没搬，两种都要有），对不上的文件数必须是 0」：

- `CORPUS.md` 227 / `COVERAGE.md` 227，**对称差 0**
- 其中 **55 个文件记的是「查过没有可搬的」**

⚠️ **这一票用了 `FG-01` 刚定的规矩**：覆盖记录是一条命令的输出，不是一张手写清单 ——
手写清单会窄在写它的人的印象上。

## 引出了什么新的未知

**批 3–5 的 180 个文件是靠信号词筛的，不是逐行读的。**
信号词漏掉的段落，`COVERAGE.md` 会把那个文件记成「0 段」——
**看起来和真的没有可搬的一模一样。** 这条判据证明了「没漏文件」，
**证明不了「没漏段」**。要更强的保证只能逐行读，那是下一轮的事。
