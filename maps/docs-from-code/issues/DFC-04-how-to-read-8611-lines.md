## Question

人逐行读 227 个文件不现实；全自动提取分不出「为什么这么设计」和「这一行在干什么」。

要定一个**能走完全集**的做法：分批的切法（按仓？按域？按注释密度？）、
顺序、每批多大、谁判、怎么记录「这一批过了」。

⚠️ **不要做成抽样。** 上一张图就是因为范围写窄而漏掉两批，
这张图的锚是 [CORPUS.md](../CORPUS.md) 的 227 行，**少一个文件都不算完**。

⚠️ **2026-09-16 由 `DFC-01` 带出来**：判据的单位是**段**不是文件，而生成的代码和我们写的
混在同一个文件里（`ethernetif.c` 就是）。所以这张票要先定**锚是文件还是段** ——
`CORPUS.md` 现在按文件计 227 个。

## 怎么算答完


跑完之后，拿 `CORPUS.md` 逐文件对：**每一个文件都有一条记录说它处理过了**
（搬了什么 / 什么都没搬，两种都要有记录）。对不上的文件数必须是 0。
