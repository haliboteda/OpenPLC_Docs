## Question

8,611 行里显然不是每一行都要搬走。要先有一条能判真假的线。

初步观察到的几类，等着被判：

| 形态 | 例 |
|---|---|
| **为什么这么设计** | `owner_slot.c`「谁先到谁赢，这是产品形态的后果」 |
| **需求编号引用** | `iap_cert.h`「Requirement C11」 |
| **判据 / 阈值** | `porttool.h`「见 DECISIONS 37」 |
| **这一行在干什么** | `use_utf8_stdout()`「在中文 Windows 控制台上把标题打对」 |
| **给编译器/工具看的** | `// noqa: E402`、`_Static_assert` 旁边的解释 |
| **陷阱警告** | `port_din.h`「这个脚外部是输出，所以不配内部上拉」 |

⚠️ **「陷阱警告」是最难判的一类**：它既是设计结论，又是下一个改这行代码的人**必须当场看到**的东西。
搬走它可能正确，也可能等于把地雷的标记撕了。

## 怎么算答完


给出一条判据，拿 [CORPUS.md](../CORPUS.md) 里注释最重的 **10 个文件**逐行试，
每一行都能无歧义地落进「搬走 / 留下」，**没有一行需要临场发挥**。
并且对「陷阱警告」这一类给出明确处理，不是回避。
## 进行中的发现（2026-09-16，票还没关）

**用户给了判据**（原话）：

> 「只要是结论性的都可以留在注释里，我要精简的是那种**描述修改过程、描述为什么、原因是什么**那种。」

在五处真注释上试过，切得动（例子见 [../TODO-PLAN.md](../TODO-PLAN.md)）。

⚠️ **但读到语料里最大的那一段（`TestCase/CAN/can_test.h`，223 行）时，两分法不够了。**

那 223 行几乎全是**硬件事实**：引脚表、BGA ball 号、收发器型号（ISO1044BDR）、
隔离电源（U7 装在背面）、端子映射、JP7 出厂开路、R83/R84 DNP、以及一条
「Klemmblockzuordnung.pdf 第 4 页从端子 09 起是错的」的陷阱。

它既不是「这段代码要达成什么」，也不是「为什么这么设计」，而是**从原理图/网表抄过来的一份拷贝**。

按 `结论 / 为什么` 两分，这 223 行会被判成「结论，留下」—— **那是错的**：

- `verify-dont-assume` 规矩写着：**固件、core、变体头都是抄件，不能当唯一出处**
- `REFERENCE-LAYER-TAXONOMY` 写着 `hardware/` 的**出处只能是原理图 / 网表 / 数据手册**
- `docs/hardware/HARDWARE-FACTS.md:289` 已经记着那条 C09/C10 陷阱，并点名它**当时还住在固件两处** ——
  也就是说这份重复是已知的，只是没人去收

**所以判据要三分，不是两分**：

| 类 | 去哪 |
|---|---|
| 结论 + 一句话为什么 | **留在注释里** |
| 成段的论证、权衡、修改经过 | **搬进设计文档** |
| **硬件事实的拷贝**（引脚、型号、端子、跳线状态） | **搬进 `docs/hardware/`，注释里只留一条指针** —— 它的权威出处是原理图，固件本来就只是抄件 |


## Answer

2026-09-16 定。**判据是三分，不是两分**，而且单位是「段」不是「文件」。

| 类 | 去哪 |
|---|---|
| 结论，或结论 + **一句话**为什么 | **留在注释里** |
| **成段的**论证、权衡、取舍、修改经过 | 搬进文档（设计 / 需求 / 测试，看内容） |
| **抄自原理图 / 网表 / 数据手册 / 外部规范的原文** | **谁都不抄 —— 注释里给一条链接** |

第三类用户的原话：**「如果是抄原理的，都一律给连接，不抄原文。」**
已升成通用规矩，见 `AI-Skills/_shared/rules/docs-before-code.md`。

### 验证

票的判据是「拿注释最重的 10 个文件逐行试，没有一行需要临场发挥」。
10 个文件、**261 段 / 1,898 行**：逐段读了开头，超过 14 行的大段读全文。
**每一段都落得进上面三类之一，没有落不进去的。**

**这一遍试出两个洞，都不是靠想出来的：**

1. **硬件事实是第三类**（`TestCase/CAN/can_test.h` 开头 186 行、`knx_test.h` 开头 231 行）。
   两分法会把它们判成「结论，留下」—— 而那正是 `verify-dont-assume` 禁止的：抄件不能当唯一出处。
2. **生成的代码和我们写的混在同一个文件里**（`LWIP/Target/ethernetif.c` 的 153 行注释里，
   既有 ST 的 `@brief` 模板，又有 USER CODE MACADDRESS 块 —— **那块是九条跨仓镜像之一**）。
   所以整份排除会连镜像一起漏掉，**单位必须是段**。含生成痕迹的共 6 个文件、368 行。

### 「修改过程」有明码标记，可以先用机器捞

语料里这几种形态几乎总是修改经过，可以自动标出来给人复核，不用逐行肉眼找：

- `***`（项目自己的强调标记，常跟在「以前是……后来改成……」后面）
- `used to be` / `used to sit here` / `Before that this`
- `A real board failure, <日期>` / 带 `2026-XX-XX` 的叙述句

## 引出了什么新的未知

**语料表的口径要不要按段重算。** 现在 `CORPUS.md` 是按文件计的 227 行，
但判据的单位是段。**「全做完」的锚是文件还是段**，会改变 `8,611 行怎么读完而不是抽样` 那张票的做法 ——
已在它的题面里点出。
