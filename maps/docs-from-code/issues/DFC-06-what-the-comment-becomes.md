# 注释和文档怎么保持同步

Type: grilling
Opened: 2026-09-16
Status: resolved
Blocked by: DFC-01

## Question

⚠️ **2026-09-16 改过题面。** 原来问的是「搬走之后留什么」——
但用户当天定了**注释内容不动**，所以问题变成：**两边都在，怎么不让它们分叉。**

用户同一天给了半个答案：

> 「**分清楚是结论还是引用。结论可以直接写，如果是引用定期同步。**」
> 「**就算代码里要写理由也要写引用位置。**」

所以要定的是剩下那半：**「定期同步」具体是什么东西在跑。**
引用会过期而且过期时通常没有任何东西报警 —— 这次搬迁就让 66 处代码注释里的路径指空了，
P8/P9 一条都看不见（它们只读 `.md`）。

## 怎么算答完


有一个**真的会跑的东西**在查引用有没有过期。
拿这次的真样本验：**故意把一处注释里的引用位置改错，它必须报出来。**
说得出规则但没有东西去跑，不算答完。
## Answer

2026-09-16 定。分两半，两半都齐了。

**规则那一半（用户当天给的）**：

| 注释里这一句是 | 怎么办 |
|---|---|
| **结论** —— 这段代码自己的事实 | 直接写。它不会从别处变，不用同步 |
| **引用** —— 指向别处的事实 | **写引用位置，并纳入定期同步** |

已升成通用规矩，见 `AI-Skills/_shared/rules/docs-before-code.md`。

**跑的那一半**：就是 P9。`检查只读 .md 是个盲区`
（`maps/framework-gaps/issues/FG-02-checks-only-read-markdown.md`）
把它扩到了源码注释 —— **1,220 个源文件里每一条指向文档的引用都被逐个 resolve**。

引用过期 = 指不到东西 = P9 报错 = `selfcheck` 红。**这就是「定期同步」的实体。**

### 验证

票的判据是：**故意把一处注释里的引用位置改错，它必须报出来；说得出规则但没有东西去跑，不算答完。**

拿 `$BOOT/IAPServer/owner_slot.h` 里一处改回搬迁前那个已不存在的路径：

```
  open_plc_cube_ide\IAPServer\owner_slot.h:4  ->  <搬迁前那个旧路径>
  1 reference(s) name a file that does not exist     exit=1
```

**报出来了。** 恢复后 522 条引用全部存在。

⚠️ **这条判据在 2026-09-16 之前是不可能满足的** —— 那时 P9 只读 `.md`，
源码注释里的引用一条也看不见，66 处指空整整半天没有任何东西报警。

## 引出了什么新的未知

**P9 只管「指不指得到」，不管「指得对不对」。**
一条引用可以指到一个存在的文件，而那个文件已经不讲那件事了 —— 检查照样绿。
这一类漂移目前没有任何东西看得见。
