# 那几处「唯一出处就是代码注释」怎么办

Type: grilling
Opened: 2026-09-16
Status: resolved
Blocked by: -

## Question

有三处是**刻意**把出处放在代码里的，和这张图的终点正面冲突：

| 在哪 | 原话 |
|---|---|
| `ARCHITECTURE.md:50` | `check_core_sync.py` 刻意排除六类，「每一类为什么排除写在脚本自己的 `SKIP` 注释里 —— **那是唯一出处，这里不抄**」 |
| `TEST-CASES.md:54` | 「本文件只管判据和运行方法（**贴着代码走，跨仓不搬**）」 |
| `FILE-DESTINATIONS.md` | 四份 README 2026-09-16 定为**留在原地**，理由是「它描述的就是所在目录」 |

要定：这三处是这张图要推翻的，还是它要保留的例外。

⚠️ **它们都不是疏忽，都是当时写下理由的决定。** 推翻要给出比原理由更强的理由。

## 怎么算答完


三处各有一个结论：推翻 / 保留 / 改形态。推翻的那些，原文档里的那句话当场改掉，
不留两种说法。
## Answer

2026-09-16 定。**三处一个都不推翻。** 用户当天给的规矩把这道题解开了，不用二选一：

> 「**就算代码里要写理由也要写引用位置。**」

理由留在原地，但它得说出完整版在哪 —— 所以「贴着代码」和「文档最全」不矛盾。

| 处 | 结论 |
|---|---|
| `check_core_sync.py` 的 `SKIP` 注释 | **保留为唯一出处。** ⚠️ 我一度怀疑那些逐类理由根本不存在，**核实后是存在的**（脚本第 30–54 行，六类各有一段）。已给脚本补上回指 `ARCHITECTURE.md` 的一句 |
| `TEST-CASES.md` 的「贴着代码走，跨仓不搬」 | **那句话自己作废了** —— 本文件 2026-09-16 当天就搬进了 `OpenPLC_Docs`。已改掉，并写明真正贴着代码的只剩四份主机侧 README |
| 四份主机侧 README 留在原地 | **保留。** 它们描述的就是所在目录，且 `TEST-CASES.md` 已给每一份补了指针 |

### 顺带改掉的一个真错

`TEST-CASES.md` 里那条链接的文字是 `open_plc_cube_ide/docs/STATUS.md` —— **一个搬迁前的路径**。
链接目标能解析（同目录），所以 P9 抓不到；**错在给人看的那半**。已改成 `STATUS.md`。

## 引出了什么新的未知

**P9 只验链接指得到东西，不验链接文字说得对不对。** 这次那条就是目标对、文字错，
检查全绿。**不知道这种还有多少**，也不确定值不值得查 —— 记一笔。
