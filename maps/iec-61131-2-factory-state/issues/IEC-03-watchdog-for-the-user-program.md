# 用户程序卡死时谁发现、输出怎么办

Type: grilling
Opened: 2026-09-28
Status: resolved
Blocked by: IEC-02

## Question

标准 2003 5.8 要求有监视用户程序的手段（看门狗）。要定：app 这边开不开 IWDG、由谁喂（core 在两次 `loop()` 之间喂，还是交给 sketch）、超时之后是复位还是先把输出置到规定状态、和 bootloader 交权时的看门狗状态怎么衔接（`$BOOT/IAPServer/IAP_boot_handoff.c`）。

## 怎么算答完

定下开不开、谁喂、超时行为；一个故意卡死的 sketch 在真板子上被发现，输出落到规定状态。

## Answer

2026-10-03 定（用户按推荐定，分两轮）。

| 事 | 定案 |
|---|---|
| 谁开、谁喂 | 板卡包默认开 IWDG，每跑完一次 `loop()` 喂一次；bootloader 不开 |
| 超时 | 进 `setup()` 前按 32 s（硬件上限）开，`setup()` 返回后改成默认 2 s；`setup()` 里可调，最长 32 s |
| 超时以后 | 硬件复位，DO 和继电器落在断开（见「每个输出在上电、掉电、没有 app、app 刚起来时处于什么状态」）；AO 另见「AO 在上电和掉电时怎么落到确定值」 |
| 反复卡死 | 连续 3 次被看门狗复位就停在 bootloader 不跑 app；断电重新上电、或 app 连续正常跑满 60 s 清零。计数在 RTC 备份寄存器 DR5，bootloader 累加、app 清零 |
| 停住时 | 系统指示灯慢闪（1 s 一次）一直闪；串口每次开机打一行原因；照常应答发现和上传 |

理由：用户不写任何代码就满足标准 2003 5.8 的「监视用户程序」；偶发卡死自己恢复，反复卡死不让负载跟着复位反复动作。
