# 已知问题和待立项模块在新框架里住哪

Type: grilling
Opened: 2026-09-16
Status: resolved
Blocked by: -

## Question

wayfinder 的票按定义是**决策票** —— 提一个问题，答完就关。但旧框架里有两类东西不是决策：

- `ISSUES.md` 的 **6 条** `ISS-*` 是**已知缺陷**。`ISS-B2`「两块板 MAC 是否不同」没有决策可做，它等的是第二块板
- `BACKLOG.md` 的 **1 个**待立项模块（单张证书撤销 C12）状态是 ⬜「等一个真实需求」

**这两类在新框架里没有位置。** 要定它们是什么：票的第五种类型、参考层的一张表、
还是各自单独一张图。

⚠️ 这是换框架暴露出来的，不是搬迁带来的 —— 旧框架里它们是文件，所以看不出问题。

⚠️ **开票时题面写的是「11 条 ISS-* 和 8 个 M*」，那是照抄 `ID-MAP.md` 来的，错的。**
核实后：`ISSUES.md` 实有 6 条，`ID-MAP.md` 多列了 `B4`/`E1`/`F1`–`F5` 七条早已删掉的，
又漏了真实存在的 `ISS-D2`；`M1`–`M8` 已全部完成，`BACKLOG.md` 只剩 1 个。
**手维护的编号登记表会漂，这件事本身就是这张票的证据。**

## 怎么算答完

6 条 `ISS-*` 和那 1 个待立项模块 **每一条**都能指出它在新框架里的确切位置，没有一条「不知道放哪」。
并且能说清**一个已知缺陷什么时候算关掉** —— 它和决策票的关闭条件不是一回事。

## Answer

2026-09-16 定。路由表写成 [../../../WHERE-THINGS-LIVE.md](../../../WHERE-THINGS-LIVE.md)。

**核心结论：「已知问题」不是一类东西，所以不给它一个统一的新家。**
给它一个统一的家，就是把旧框架的洞原样搬过来。拆成五个去处，按顺序问：
票 / 参考层 / `work/` / `waiting/` / 迷雾。

两条准入是硬的：

- **`work/` 的每一条必须写明它是哪张已关的票产生的。** 写不出来的写不进去 ——
  旧框架里谁都能往 `ISSUES.md` 添一行，所以它既是待办表又是垃圾桶
- **`waiting/` 一行写两样：等什么 → 到了之后立刻做什么。** 这类东西的真实风险不是忘了记，
  是条件到了没人想起来

### 缺陷什么时候算关掉（题面要求说清的那一问）

和决策票**不是一回事**：

| | 关闭条件 |
|---|---|
| 决策票 | **答完就关**，不是做完 |
| `work/` 的一条 | 做完**且判据过了**，删掉那一行。不划掉留着 |
| `waiting/` 的一条 | 条件到了，转成 `work/` 的一条或一张票，然后删掉 |

### 验证

`怎么算答完` 要求 6 条 `ISS-*` 和那 1 个待立项模块每一条都能指出确切位置：

| 条目 | 去哪 | 为什么 |
|---|---|---|
| `ISS-B1` `[BOOT] millis=` 靠电荷泵余电 | **票** | 两条路等一个决定 |
| `ISS-C1` 校准值存哪 | **票** | 等用户定 |
| `ISS-B2` 两块板 MAC 是否不同 | **`waiting/`** | 等第二块板 → 到手第一件事就跑它 |
| `ISS-A3` PG9 挪进 `.ioc` | **`work/`** | 要做什么已清楚 |
| `ISS-D1` 异常可恢复 | **`work/`** | 同上，做法上一轮已想好 |
| `ISS-D2` 面板按九类分段 | **`work/`** | 同上 |
| C12 单张证书撤销 | **迷雾** | ⬜「等一个真实需求被顶上来」—— 知道有这件事但还问不清楚 |

七条全部落位，没有一条「不知道放哪」，也没有一条同时像两个去处。

⚠️ **顺带把 `逐份定去向` 那张票剩的六行也定了**（它等的就是这个答案），
`docs/modules/` 现在 43 行全部定死，没有待定项。

## 引出了什么新的未知

**`ID-MAP.md` 该不该改成脚本扫出来。** 这张票核实时发现它手维护已经漂了 ——
多列 `ISS-B4`/`E1`/`F1`–`F5` 七条早删掉的，又漏了真实存在的 `ISS-D2`。
**一张手维护的「现在有哪些编号」表会漂，这本身就是个记录方式的洞**，
但它属于「编号体系怎么办」那片迷雾，不在这张票里做。已记进图。
