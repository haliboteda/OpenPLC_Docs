# 入口：从哪儿进，做到哪了

**这份是整套文档的入口。** 它只回答三件事：**你的处境该看哪份** · **有哪几个模块** · **现在做到哪了**。

具体到某条需求要做到什么、某个测试怎么跑、判据是什么 —— **一律在模块文档里**，这里不抄。

---

## 一、你的处境，该从哪份看起

带 ✋ 的场景**需要你到板子跟前动手**，其余都能在电脑上完成。

| 你的场景 | 谁动手 | 从这里看起 |
|---|---|---|
| 新板到手，先把程序跑起来 | 你 | [M1 · 一次上传是怎么走完的](../modules/M1-firmware-upgrade.md) |
| 把这块板变成我的 | **✋ 你** | [M2 · 信任根的一生](../modules/M2-ownership.md) |
| 日常升级一块已认领的板 | 你或同事 | [M1 · 一次上传是怎么走完的](../modules/M1-firmware-upgrade.md) |
| 让同事也能上传，但不给他根私钥 | 管理员 | [M2 · 发证书：全程不碰板子](../modules/M2-ownership.md) |
| 同事离职，或他的叶私钥泄露了 | 管理员 | [M2 · 信任根的一生](../modules/M2-ownership.md) |
| 我把根私钥丢了 | **✋ 你** | [M2 · BOOT0 手势：一次按压，三个结果](../modules/M2-ownership.md) |
| 板子起不来 / 一直停在 bootloader | 你 | [M1 · 板子起不来怎么查](../modules/M1-firmware-upgrade.md) |
| 我用 ST-Link 换过 bootloader | **✋ 你** | [M2](../modules/M2-ownership.md)，再回 [M1](../modules/M1-firmware-upgrade.md) |

## 二、有哪几个模块

**划分标准：一个模块回答「这条没做到，外面的人就失去了让板子做某件事的能力」。**

| 模块 | 外面的人能让板子做什么 |
|---|---|
| [M1 固件升级](../modules/M1-firmware-upgrade.md) | 把新固件装进去，装不坏 —— 找得到板子、只让有授权的人装、装到一半断电也不变砖 |
| [M2 归属与信任](../modules/M2-ownership.md) | 把板子绑到自己的钥匙上，能发证、能收回 |
| [M3 应用运行环境](../modules/M3-app-runtime.md) | 自己写的 sketch 能用板子的资源，且不被 bootloader 坑 |
| [M4 产线工装](../modules/M4-production-fixture.md) | 硬件工程师逐路自测板上每个端口 |
| [工程约束](../engineering/README.md) | **不是板子的能力** —— 它回答「我们怎么保证板子一直做得到」，按「**我现在处在开发流程的哪一步**」分节 |

## 三、做到哪了

| 符号 | 含义 |
|---|---|
| ✅ | 已实现**且**有实测证据，**且证据仍然成立** |
| ⚠️ | 曾经通过，但**证据已经失效**（系统变了 / 硬件变了），要重跑 |
| 🟡 | 已实现，但**没有测试能证明**它（或只测过一半） |
| ❌ | **测了，不过** |
| ⬜ | 未做 |
| ⛔ | 明确不做 |

> ⚠️ **🟡 才是这张表最有用的部分。** ✅ 和 ⬜ 都不会骗人；🟡 会 —— 功能在跑，没人测，改坏了也没人知道。

## 四、必须做的测试，按优先级

| 优先级 | 做什么 | 为什么是这个位置 | 挡在哪 |
|---|---|---|---|
| **P0** | **两块板 MAC 不同**（`R1-14`） | 派生算法撞了的话，量产时表现为**同网段大面积 IP 冲突**，那时已经晚了。逐板检查单（`ENG-09`）跟着一起卡 | **第二块板**。⚠️ 板子到手第一件事就是这条 |

**为什么到 P1 为止**：剩下两条 🟡（`R1-14` MAC 唯一、`ENG-09` 逐板检查单）卡在同一件事上 —— 第二块板。`R2-04`（撤销叶子证书）不在这张单子上：换根已经是可用的撤销手段，它等一个真实需求。
