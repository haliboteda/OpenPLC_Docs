# 收尾

**用户说"今天结束 / 到此为止 / 今天就这样"不是道别，是一条指令。** 把这一天产生的、**不属于项目代码本身**的东西全部归位进仓库并提交：脚本、工具、实测结论、设计决策、教训。

判断做完没有只有一条标准：

> 从零开一个新会话，照着这些文件能不能接着干？不能就是没归纳完。

## 为什么这是硬要求

留在 `%TEMP%` 或 scratchpad 里的东西**不进 git** —— 下次找不到，别人拿不到，于是同一个脚本被重写一遍。

2026-08-16 犯过一次：自动烧写脚本写进 scratchpad，还硬编码了绝对路径 —— 双重报废。所以这是 `$PROD/docs/repo/CONVENTIONS.md` 里的正式约定，不是建议。

## 步骤

1. **对照下面那张表**，逐行看今天做过的事该归到哪。
2. **逐项归位。** 每一项都落到仓库里的固定位置，不是 scratchpad。
3. **人工过一遍 `$BOOT/RELEASE-NOTES.md` 的 known-issues 和 not-verified 两节**，逐条问"今天这条还成立吗"。
   ⚠️ **这一步没有任何自动化能替** —— `selfcheck` 只抓得住版本号那一种形态。
4. **跑一遍受影响的自检**，别把红的留给下一次开会话的人。
5. **提交每一个动过的仓库。** 分支各不相同，用每个仓库当前的分支，**不要假设是 `master`**。
6. **报告**：哪些仓库、哪些 commit、还剩什么没归位以及为什么。

## 归到哪 —— 这张表是唯一出处

| 今天产生了 | 归到哪 |
|---|---|
| 测试脚本、自动化工具 | `$TOOL/TestCase/tools/` 或 `host/<主题>/`，判据写进 `$PROD/docs/tables/TEST-CASES.md` |
| 一次性探查脚本，但值得留 | 同上，并补一份 README 说清"验证什么 / 前置 / 判据" |
| 新的设计决策与否决理由 | `$PROD/docs/tables/DEFERRED-DESIGNS.md` 或对应模块的 Todo 文件 |
| 新发现的问题 | ISSUES.md（零散）或 BACKLOG.md（要立项） |
| 需求状态变化 | `$PROD/docs/tables/STATUS.md` 的状态列 |
| 用例跑出来的结果 | `$PROD/docs/tables/STATUS.md` 的「最近结果」和「证据日期」两列 |
| 协作方式上的教训 | 只对本产品成立的进 `$PROD/docs/repo/CONVENTIONS.md`；换个项目也成立的进 `<AI-Skills>/_shared/rules/`，然后跑 `_shared/sync_rules.py` |

**表里没有的类别，先问，不要自己发明位置。**

## 不要做的事

- **不要**把今天的结论只写在对话里。对话不进 git。
- **不要**为了让收尾看起来干净而删掉没做完的东西 —— 没做完就写进 Todo，连"为什么停在这"一起。
- **不要**假设用户要推送。**问一次** —— push 是外向操作，说过一次"全部提交"不等于永久授权。
