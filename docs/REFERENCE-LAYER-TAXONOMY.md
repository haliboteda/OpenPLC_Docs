# 参考层的分类

**参考层收什么、按什么分。** 定于 2026-09-16，由
`maps/docs-migration/issues/MIG-02-reference-layer-taxonomy.md` 这张票敲定。

## 准入判据只有一条

> **不会因为工作推进而变的，进参考层。还在动的，一律是票或图。**

「还在动」的典型形态：差距表、待填结果、计划、待办、已知问题。
旧框架里它们只能当文档存着 —— **那正是「没有位置放未定的事」这个洞的表现**，不是文档该有的样子。

## 八类

按**问题域**分，不按产物类型（`design/` `work/` `test/` 那种）分。
理由：主读者是 AI 会话，它要回答的是「我在改 RS485，该读哪几份」，
按产物类型分是按「谁写的」分，答不了这个问题。

| 类 | 收什么 | 边界 |
|---|---|---|
| `hardware/` | 板子的真相 | **出处只能是原理图 / 网表 / 数据手册**。固件、core、变体头都是抄件，不能当唯一出处 |
| `boot/` | 启动、升级与通信协议 —— bootloader ↔ 上位机那一套 | ⚠️ 目前只有一份，见下面的空缺 |
| `security/` | 证书、密钥、owner 记录、信任根 | |
| `production/` | 产测与工装：方案文件、步骤类型、配置项、判据 | |
| `build/` | 编译、烧写、版本同步、CubeMX 硬规矩、工程结构 | |
| `repo/` | 三仓分工、跨仓镜像、写文档的约定、跨仓硬约束 | |
| `outbound/` | 给外人的 | **判据和别处不同**：必须自成一体、不能引内部链接、发出去之后改了要重发 |
| `tables/` | 按编号索引的总表 | 见下 |

## 两个刻意的例外

**总表不按域拆。** 决策 48 条、用例、编号登记、需求定义横跨所有域，
但**它们的组织原则本来就是编号，不是域** —— 编号本身就是一种索引。
硬按域切会让「`DECISIONS 44`」这类外部引用全断，而「不要重开」这条线全靠那些编号当锚点。
各域入口只放一行指针，不抄内容。

**状态表要拆成两半。** 需求定义（53 条主张）不随工作变，进 `tables/`；
「最近结果 / 证据日期」是跑出来的，**不进参考层** —— 那是测试工具的输出，
人手抄进文档正是它三个数字对不上的原因。

## 已知的空缺

`boot/` 只有一份 journal 设计。**IAP 协议是这个产品的核心，参考层里却没有它的独立文档** ——
它一直只活在代码注释和决策条目里。这是个真空缺，已记进
`maps/docs-migration/map.md` 的迷雾，不是分类没分好。
