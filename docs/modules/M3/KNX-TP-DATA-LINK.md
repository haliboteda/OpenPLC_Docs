# KNX TP 数据链路层（STKNX，定时器收发）

`OpenPLC_KNX` 在 TP 总线上怎么收发。定于 [KNX 库的 TP 收发怎么在本板上发出合法帧](../../../maps/core-examples-on-board/issues/EXB-08-how-does-the-knx-library-drive-stknx.md)；
引脚、极性和收发链电路在 [HARDWARE-FACTS.md](../../hardware/HARDWARE-FACTS.md)「KNX 接口」，这里不抄。

## 结论

| 是什么 | 为什么 |
|---|---|
| **新写 `StknxDataLinkLayer` 替换协议栈里的 `TpUartDataLinkLayer`**，三个带 TP 的角色（0x5780、0x07B0、0x091A）都换；上层协议栈不动 | STKNX 是裸 TP1 收发器，没有 TP-UART 那套字节级主机协议，原来那层在跟一个不存在的芯片说话 |
| **位由定时器产生和捕获**：TIM12_CH1 在 `KNX_TX` 上出脉冲，TIM1_CH3 捕获 `KNX_RX` 的下降沿 | 逻辑 0 是 35 µs 的有源脉冲、位周期 104 µs，UART 产生不了这种波形；时序照搬工装固件 `$BOOT/TestCase/KNX/knx_test.c`，那套在真总线上收发过 ETS 看得见的帧 |
| **捕获下降沿**（工装捕获的是上升沿） | `KNX_RX` 低有效，下降沿才是脉冲起点；冲突要在脉冲一出现就判，等到上升沿就晚了 35 µs |
| **每个位周期的输出提前一拍写进预装载寄存器** | 在更新中断里改当拍的比较值，中断延迟那 1–3 µs 会在 `KNX_TX` 上漏出一个毛刺脉冲 |
| **收字节、组帧、应答、冲突、重发全在两个定时器中断里做**，`loop()` 只搬整帧 | 应答必须在帧尾后 15 个位时间发出（约 1.6 ms），sketch 里一个 `delay()` 就会错过 |
| **`OpenPLC_KNX` 的 `setup()` 第一件事把 PB14 推挽拉低**，不论哪个角色 | PB14 悬空时收发器一直从总线抽流，见 HARDWARE-FACTS「PB14 绝不能悬空」 |
| **用了这个库，TIM1 和 TIM12 就归它**，sketch 不能再拿这两个定时器做 PWM 或别的 | 两个定时器整个被重配（预分频、周期、中断） |

## TP1 链路规则（库里实现的）

| 项 | 取值 | 出处 |
|---|---|---|
| 位周期 / 有源脉冲 | 104 µs / 35 µs | STKNX 数据手册 DocID031327 Rev 1 §5.1 |
| 一个字节 | 起始 0 + 8 位数据（低位先）+ 偶校验 + 停止 1，字节间 2 位空闲 | 同上；[KA] p.22；[TPU2] §3.2.1 |
| 校验字节 | 前面所有字节异或后取反 | [KA] p.21「交叉校验」；协议栈 `CemiFrame::calcCrcTP()` |
| 发帧前总线要空闲 | 50 个位时间；普通、低优先级的首发帧再加 3 个（共 53）；对方回 BUSY 后 150 个 | 50 和加 3：[KA] p.22–23（t3、t1）；150：[NCN] p.36 |
| 应答 | 校验字节的停止位之后 15 个位时间发一个字节：ACK `0xCC`、NAK `0x0C`、BUSY `0xC0` | [TPU2] §3.2.3.1.11 Fig.28；[KA] p.21–23；工装在真总线上收到过 47 个 ACK |
| 什么帧要应答 | 协议栈说「这个地址是我的」（`isAckRequired()`）且校验对就回 ACK，校验错回 NAK，收件队列满回 BUSY；自己发的帧不应答 | [KA] p.21 |
| 重发 | 没等到 ACK、收到 NAK 或 BUSY 时重发，最多 3 次（NAK 和 BUSY 共用这一个计数 ¹），重发帧清掉控制字节的「未重复」位 | 3 次：[TPU2] §3.2.3.1.9.4、[NCN] p.36；重复位：[KA] p.20 |
| 冲突 | 自己这一位不发脉冲、总线上却出现了脉冲 = 仲裁输了，当即停发，那一帧照常收下来，总线空闲后重发（不算重发次数） | [KA] p.21（CSMA/CA） |

出处（2026-10-03 核对；KNX 规范原文 Vol 3 Part 2 Ch 2 没有公开版本，以下都不是规范原文）：

| 代号 | 文档 |
|---|---|
| [KA] | KNX Association，*Serial Data Transmission and KNX Protocol*（KNX Tutor Seminar，E0808f） |
| [TPU2] | Siemens，*KNX EIB TP-UART 2+ IC* Technical Manual，2013-08 |
| [NCN] | onsemi NCN5130 数据手册 Rev. 4，2019-08（NCN5120/5121 同节文字相同） |

¹ **NAK 和 BUSY 共用一个重发计数没有出处**：两家接口芯片（[TPU2] [NCN]）是各计各的，规范原文怎么要求没核实到。只在 NAK、BUSY 交替出现时有差别（这里最多发 4 次，芯片最多 7 次）。上板时用 ETS 总线监视器确认对方认我们的应答、我们也认对方的。
