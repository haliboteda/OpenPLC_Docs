# M2 · 归属与信任

> ⚠️ **代码已按[决策 72](../tables/DECISIONS.md) 实施（未提交、未上板验收）**，见 [work/TODO.md](../../work/TODO.md)「出厂无根、第一次上传自动认领」。

**外面的人能让这块板做什么**：把它绑到自己的钥匙上，从此只有自己能往里装固件；
把这个权力交给别人；丢了钥匙时把板子收回来重新开始 —— **全程不需要 ST-Link，也不重编、不重写 bootloader**。

**这个模块管到哪为止**：从「这块板现在信哪把根」这个问题，到「这张证书是不是那把根签的」这个回答。
**拿到答案之后怎么装固件**不在这里，在 [M1 固件升级](M1-firmware-upgrade.md)。

## 1 · 信任根的一生

```mermaid
stateDiagram-v2
    direction TB
    [*] --> 没有根: ST-Link 烧 bootloader + 校准值

    没有根: 没有根（根区空）
    没有根: 不跑 app，只接受 takeown

    已认领: 已认领（G1…Gn）
    已认领: 用链尾那条记录里的根

    没有根 --> 已认领: 第一次上传，IAPTool 自动 takeown<br/>追加 G1，无签名（TOFU）<br/>USB 或网口，不设门
    已认领 --> 已认领: setowner<br/>追加 G(n+1)<br/>必须被 G(n) 签名
    已认领 --> 没有根: 恢复出厂<br/>追加 cleared 记录<br/>门控 = 按住 BOOT0 满 10 秒

    note right of 没有根
      回到这里就是回到 TOFU：
      下一次上传的人认领
    end note
```

**三个操作都只往根区追加，不擦除**；根区写满时由扇区 15 的回收压缩，见 [扇区 15 设计说明](M1/SECTOR-15.md)。

| | 操作 | 对根区做什么 |
|---|---|---|
| ① | 认领 `takeown` | 往空区追加 G1。**没有前任可以签它 = TOFU**。IAPTool 在上传时发现板子没有根就自动做这一步 |
| ② | 换 owner `setowner` | 追加 G(n+1)，**必须被 G(n) 签名**，否则 bootloader 忽略。不限次数，不碰 bootloader |
| ③ | 恢复出厂 | 追加一条 `cleared` 记录。链尾是 cleared → 回到没有根，回到 TOFU |

**② 是这套东西真正安全的原因**：攻击者即使能往 flash 写字节，写出来的记录也过不了 G(n) 的签名校验。

出货工具入口：IDE 上传（`IAPTool cdc` / `ether`，无根时自动认领），以及 `IAPTool getowner / takeown / setowner`。

### `getowner` 的线上契约

**板子回一个纯数字，没有别的** —— 当前生效那条记录的 `generation`。

⚠️ **`0 = 从没被认领过`，但反过来不成立**：**恢复出厂写的是一条 `OWNER_FLAG_CLEARED` 记录，
generation 照常递增**，所以一块刚恢复出厂的板子回的是非 0。
**线上没有任何字段能表达「已清空」，而且刻意不加**（2026-09-21 定）：

| 加字段的办法 | 为什么不做 |
|---|---|
| `getowner` 改回两个字段 | IAPTool 和 **6 个测试脚本**都用整串解析成数字，会一起挂 |
| 已清空时回 `0` | `setowner` 要用 generation 算下一条记录的签名前缀，回 0 就签错 |
| 新增一个查询命令 | 查过三处（产线、出厂态验收、6 个脚本），**没有一个调用者需要它** |

**由此得到两条工具侧的规矩**：

1. **「板子有没有根」问 `getpubkey`，不问 `getowner`** —— 没有根时 `getpubkey` 回 `none`（[IAP-PROTOCOL.md](M1/IAP-PROTOCOL.md)）。
   `takeown` 本身不做前置判断，由 `owner_slot_claim()` 决定；板子在「最后生效的是一条恢复出厂记录」时照样接受
2. **`getowner` 的输出要说清换主的两条路**（`setowner` 要当前主人的密钥 / 恢复出厂后下一次上传自动认领），
   而不是只说「Only firmware signed by that key will start」

见[恢复出厂之后 takeown 被工具拦下，因为线上没法表达「已清空」](../../maps/owner-revoke-and-boot-upgrade/issues/OWN-11-getowner-cannot-say-cleared.md)。

### 一把钥匙，两个问题

**整个系统里只有一种秘密：一把 ECDSA P-256 私钥，而且它永远不在设备上。** 板子持有的东西全是公开的 —— 一把根公钥，加上命令随手带来的证书。

```mermaid
flowchart LR
    K["根密钥对 K<br/>私钥在人手上，从不进设备<br/>公钥板子知道，可以公开"]
    C["证书 cert · 128 字节<br/>纸上写着叶公钥<br/>纸上的章：根私钥对前 64 字节的签名"]
    L["叶密钥对 L<br/>拿着它的人可以签固件、签 nonce"]
    K -- 签发 --> C
    C -- 指名 --> L
```

**绑定关系只有那个章** —— 没有目录、没有注册表、没有名字匹配。

板子只用这一条链回答两个问题：

| 问题 | 在哪一步问 | 怎么答 |
|---|---|---|
| **谁能上传** | 进上传模式 + 会话授权 | 他递上一张**根认可的证书**，并且用那张证书**指名的私钥签了一个新鲜 nonce** ⇒ 证明他握着某个被信任根授权过的私钥。**不是**证明他握着共享密钥 —— 板子没有共享密钥 |
| **哪个镜像能跑** | 启动验签 + 传输后验签 | **同一张证书**的叶公钥签过这个镜像。每次启动重问一遍，不是烧完问一次 —— flash 会退化，也可能事后被改 |

**证书买到的到底是什么**：让这两个问题**随时间指向不同人的密钥**，而板子不需要学任何新东西。简单模式下 **L 就是 K**（自签证书），团队模式下每个同事一把、管理员不交出根私钥 —— **板子对这两种情况没有分支**。

### 发证书：全程不碰板子

```mermaid
sequenceDiagram
    autonumber
    participant A as 管理员
    participant T as IAPTool cert
    participant C as 同事
    A->>T: 根私钥 + 同事的叶公钥
    Note over T: root_sig = 根私钥签 sha256(叶公钥)
    T-->>C: cert 文件，128 字节
    Note over C: 拿自己的叶私钥照常上传，一步不差<br/>他从未持有根私钥
```

⚠️ **这条流程完全不碰板子。** 板子从第一版就懂证书链，它只问「我信任的根，签过眼前这张纸吗」—— 纸上写的公钥是不是根自己，板子不关心，**所以没有自签特例分支**。

⚠️ **也可以直接把根私钥拷给同事** —— 能用，但想收回其中一个人的权限时只能换根，等于所有人一起重来。**人多就用证书，不要拷私钥。**

### 四条规则，各自挡住什么

| | 内容 | 挡住 | 挡不住 |
|---|---|---|---|
| **R1** | **第一次认领不设门**，USB 或网口都行（决策 72） | — | **在用户之前连上出厂板的人**：他先认领，用户上传失败后长按 BOOT0 恢复出厂再来 |
| **R2** | 换 owner 必须由当前 owner 根签名 | 已认领板子被夺走，**包括有 flash 写权限的代码** | — |
| **R3** | 恢复出厂必须物理动作，之后回到没有根 | 远程把别人的板子降级回无主 | 有物理接触的人恢复出厂后接管 |
| **R4** | 撤销只针对叶子编号，**永不能撤到一个有效根都不剩** | 把自己撤成永久变砖 | — |

**R1 挡不住的那条可以接受**：没有根的板子什么都不跑，抢先认领的人拿到的只是一块空板，用户恢复出厂就能收回。

**R3 挡不住的那条必须接受** —— 反过来不给恢复出厂，客户丢了根就是永久变砖，而他恰恰没有 ST-Link。

**R4 不是假想。** ESP32 Secure Boot v2 的 aggressive revoke 是真实反面教材，Espressif 自己的文档写着签名校验失败触发撤销时
"could also brick the device permanently if all the keys are revoked"。

### 一切的起点：出厂没有根

出厂只烧 bootloader 和校准值，**板子上没有任何根**；bootloader 代码里也不编根（决策 72）。

| 状态 | 板子做什么 |
|---|---|
| 没有根 | 不跑 app、不收上传，**只接受 `takeown`** |
| 用户第一次在 IDE 里上传 | IAPTool 取本机私钥（没有就生成），`takeown` 写进公钥，再签名上传 |

**理由**：用户拿到板子不用按键、不用 ST-Link、不用重编 bootloader 就用上自己的根；
也不再有一把人人都能签固件的公开根。

### 双模式：简单和授权链走同一条代码路径

板子**从第一版就懂证书链**，工具默认发**自签证书**（叶 = 根，K 给自己作证）。
用户体验等同单密钥；要切授权链时一条命令，**板子一个字节都不用改**。

```
简单模式（K 给自己作证）              授权链（K 签 L）
板子里: K_pub                        板子里: K_pub  ← 一个字节没变
   │ 验证书签名                          │ 验证书签名
   ▼                                     ▼
cert{ pubkey=K_pub, sig=K签 }        cert{ pubkey=L_pub, sig=K签 }
   │ 取出 K_pub                          │ 取出 L_pub
   ▼                                     ▼
镜像签名 = K 签                       镜像签名 = L 签
```

让这件事成立的三个机制，缺一条就不成立：

1. **板子里的公钥从一开始就当「根」看**，不是当「固件签名者」看 —— 升级时 K 原地升格为根，它没变，所以板子不用动
2. **简单模式也走验证书的路径**，只是那张证书自签。板子的检查恒为「这张纸的章，是我认的根能核对的吗」，**没有自签特例分支**
3. 工具**每次上传都把证书一起发**

**第 2 条是全部价值**：简单模式不是「绕过验证」，而是「验一张恰好自签的证书」，所以**不存在高级分支没人走、悄悄烂掉**。

**代价要有意识地买**：那张自签证书在安全上不增加任何东西，纯粹是 128 字节（`iap_cert.h` 的 `IAP_CERT_SIZE`）+ 一次验签，唯一作用是保住升级通道。

**客户不需要额外建根** —— 第一次上传时 IAPTool 生成的那把就是他的根，
简单模式下他只是同时也用它直接签固件。「升级到授权链」不是建新根，
而是**停止用根直接签，改用根签发的叶子来签**。

**绑定关系只有一样东西：根私钥对证书的签名。** 没有目录、没有注册表、没有名字匹配。
板子的代码两种情况完全一样，它只问「这张纸是 K 签的吗」—— 纸上写的公钥是不是 K 自己，板子不关心。

⚠️ 升级之后那张自签证书**仍然有效**（它还是 K 签的），所以**根依然可以直接签固件**。
这不是缺陷 —— 根持有者本来就是最终权威 —— 但别指望「升级后根就不能直接签了」。

### 这和 UEFI Secure Boot 是同构的

独立推出来的，事后才发现撞上了。**建议直接借用 UEFI 的术语**，读者有现成心智模型。

| 这里 | UEFI |
|---|---|
| 根区为空 → 只接受认领 | **Setup Mode**（没有 Platform Key，谁都能写） |
| T1-14 认领 | 写入 PK → 进 **User Mode** |
| 换 owner 必须被当前 owner 签名 | 改 PK 必须被 PK 签名 |
| 追加 cleared 记录，物理门控，回到没有根 | 删除 PK 回 Setup Mode，需进固件设置界面 |

| 避开 | 原因 |
|---|---|
| Android 的「**追加**一把根」（OEM 根 + 用户根并存） | Android 的 OEM 根私钥保密，多信任一把不掉安全性。**我们出厂没有根，只有用户那一把** |
| ESP32 的 aggressive revoke | 见上面 R4 |

恢复出厂的物理存在由固件在交权前判定，抄 Chromebook。⚠️ **Chromebook 背后有 TPM，这块板子没有**：这里的物理存在只是「固件在交权前读了一次引脚」，能接触到板子的人本来就能按，见上面 R3。

## 2 · 生效的那把根是怎么选出来的

照 `$BOOT/IAPServer/owner_slot.c` 的 `resolve_chain()` 画。

```mermaid
flowchart TD
    A[上电] --> B[扫 'O' 段<br/>32 条槽位]
    B --> C[取 generation 最小的有效记录<br/>从最老一条开始走]
    C --> D{这条是 cleared?}
    D -->|是| E[记下 prev_cleared<br/>继续走下一条]
    D -->|否| F{uid == 本板 UID?}
    F -->|不是| G[停止走链<br/>这条不是给这块板的]
    F -->|是| H{有签名吗?}
    H -->|没有| I{是第一条<br/>或前一条是 cleared?}
    I -->|是| J[TOFU：接受<br/>第一条不设门，见 R1]
    I -->|否| G
    H -->|有| K{能被当前生效的根验过?}
    K -->|不能| G
    K -->|能| J
    J --> L[这条成为当前生效的根<br/>继续走下一条]
    E --> C
    L --> C
    G --> M[链就地停住<br/>取停住前那条作为根]

    style G fill:#ffcccc
    style J fill:#ccffcc
```

### ⚠️ `generation` 不是用来选赢家的

**生效的那把根靠从最老一条沿链走出来，不是取 generation 最大的那条。**

「最大的获胜」是个洞：一块已被 T1-14 认领的板子上，**任何能追加记录的人都可以写一条
generation 更高的无签名记录把板子夺走**。权威必须来自链，不来自「谁排最后」。

| 这一条记录 | 要不要签名 |
|---|---|
| 第一条 | 可以没有 —— 那是初次认领（TOFU），不设门，见 R1 |
| cleared 记录 | 可以没有 —— 恢复出厂同样靠物理门控；**要求现任 owner 签名会让丢了私钥的板子变砖** |
| 紧跟在 cleared 之后的一条 | 可以没有 —— 板子已经回到 TOFU，这是又一次「第一条」 |
| 其余任何一条 | **必须由当前生效的那把根签名**，不是板子内置的那把 |

**验不过的一条会让整条链就地停住，不是跳过它继续走** —— 跳过等于让攻击者废掉一环，
就能让后面的环（在别的 owner 手下写的）静默生效。

**uid 检查排在签名/TOFU 分支之前，两边都管。** TOFU 的全部意义就是没有签名可查，
所以 uid 是「这块板的首次认领」和「别人的首次认领、字节拷过来的」之间唯一的东西。

### 记录格式（v4，两段定长）

owner 区 8192 字节切成两段，各自定长、各自追加：

| 段 | 区内偏移 | 一条多大 | 几条 | 装什么 |
|---|---|---|---|---|
| **`'O'` 所有权** | 0 | **160 字节** | **32** | 认领、换主、恢复出厂 |
| **`'R'` 作废** | 5120 | **32 字节** | **96** | 被作废的叶公钥前缀，一条一个 |

5120 + 3072 = 8192，正好占满。**两段不混排** —— 混排时一条坏记录会让它后面所有记录的
边界都算错，分段把这种传染关在一段之内。两段的比例按频率差划：换主人一生几次，
作废一生几十次（[决策 58](../tables/DECISIONS.md)）。

#### `'O'` 记录（160 字节）

```
偏移  长度  字段            说明
  0     1   type            'O' = owner 记录，0xFF = 空
  1     1   reserved0       0（v2 的 `slots` 留下的空位，保住后面字段的偏移）
  2     2   format_ver      4
  4     4   generation      单调递增。⚠️ **不是「最大的获胜」**，见上
  8     4   flags           bit0 = cleared
 12    64   root_pubkey     secp256r1 X‖Y；cleared 记录里全 0
 76    12   uid             本板的 HAL_GetUIDw2‖w1‖w0；cleared 记录里全 0
 88    64   prev_sig        上一代根对前 88 字节的签名
                            T1-14 和 cleared 都是全 0（靠物理动作门控）
152     8   reserved
                            160 字节 = 5 × 32 字节 flash word
```

#### `'R'` 记录（32 字节）

```
偏移  长度  字段            说明
  0     1   type            'R' = 作废记录，0xFF = 空
  1     1   reserved0       0
  2     2   format_ver      4
  4    12   uid             本板的 HAL_GetUIDw2‖w1‖w0
 16    16   leaf_prefix     被作废叶公钥的前 16 字节
                            32 字节 = 1 × 32 字节 flash word
```

**`'R'` 记录里没有签名，也没有 generation。** 签名在写入时验完即丢，不进 flash ——
这正好让一条记录压进一个 flash word，同时解掉 `generation` 带来的
[第二次撤销写得进去但不生效](../../maps/owner-revoke-and-boot-upgrade/issues/OWN-06-second-revocation-is-written-but-never-takes-effect.md)。

`_Static_assert` 锁死两个尺寸。**整除关系是硬要求** —— H7 一次编程一个 256 位字，
一条不是整数个字的记录没法在不读-改-写邻居的情况下追加。

#### 写入验签，读取只查结构

**`'O'` 和 `'R'` 故意不对称**（[决策 59](../tables/DECISIONS.md)）：

| | 启动时 | 写入时 |
|---|---|---|
| `'O'` | **每次重新验签**，沿链走 | 验当前根的签名 |
| `'R'` | **只查结构**（`type` / `format_ver` / `uid`），不验签、不看 generation | 验当前根对那 32 字节的签名 |

**为什么这个不对称是安全的，见 [决策 59](../tables/DECISIONS.md)** —— 一句话：
两者被伪造之后的收益差着一个数量级。

#### `setowner --wipe`：把两段清空重写

`'R'` 段满了之后，**唯一能把名额拿回来的动作是回收一次扇区 15**。`setowner --wipe`
就是为此存在的：板子照 [扇区 15 的回收流程](M1/SECTOR-15.md) 擦写一次，根区只留新主人那一条记录。

| | 平时 `setowner` | `setowner --wipe` |
|---|---|---|
| 板子做什么 | `'O'` 段追加一条 160 字节记录 | 回收扇区 15，根区清空后只写新主人那一条 |
| 掉电 | 最多留一条废记录，照常启动 | 按扇区 15 回收的掉电规则处理，bootloader 不受影响 |
| 回收名额 | 不回收 | **两段全空** |

⚠️ **板子绝不自己清空 `'R'` 段。** 剩 8 条时只提示，动作由操作者显式要求 ——
撤销记录是用户的决定，不能被一次日常换根悄悄丢掉。

⚠️ **写回去那条记录是没有签名的，而且必须没有。** 链上每一环都由前一环授权，
清空把前面那些全丢了 —— 带签名写回去的话，下次启动没有任何东西能验它，
`resolve_chain()` 会拒掉，板子回到没有根。不带签名写回去，它读起来就是一条首次认领（TOFU）。

**这没有削弱任何东西**：签名是「允许擦」的凭证，在动第一个字节之前就验过了，
而且它覆盖 generation 和本板 uid，所以抓到的命令既不能重放到这块板的以后，
也不能搬到别的板上。

generation **延续**清空前那条生效记录 +1，不从 1 重开。

#### 两条容量规则

| | 规则 |
|---|---|
| **重复作废同一个叶** | **幂等**：写之前扫一遍 `'R'` 段，前缀已存在就一个字节都不写，回 `OK already revoked`。这同时就是防重放 —— 重放一百次也只占一个 word |
| **`'R'` 段 96 条用满** | 回 `Refused`，一个字节不写。**剩 8 条时启动日志开始提醒**，引导去 `setowner --wipe` |
| **`'O'` 段 32 条用满** | 下一次换主时自动回收扇区 15，只留当前生效的那条 owner 记录；换根因此不限次数 |

⚠️ **换根不腾空名额。** 换根让旧根签发的叶全部失效（所以**不再需要**逐个撤），
但那些 `'R'` 记录仍占着 flash —— 读取不验签，板子无从分辨哪条属于哪一任根。
**真正回收撤销名额只有 `setowner --wipe`**（见上）。

#### 字段设计的理由，改格式之前必须知道

| 字段 | 为什么是这样 |
|---|---|
| `uid` 落在签名覆盖范围内（`'O'` 是 `OWNER_SIGNED_PREFIX_LEN = 88`，`'R'` 是整条 32 字节） | 签名管不到的字段谁都能改。这也是它放在 `prev_sig` 之前、而不是塞进偏移 152 的 `reserved` 的原因 |
| `'O'` 的签名覆盖 `generation` | 挡重放。一条被抓到的记录，如果 generation 不在签名范围内，就能被重放进后面的槽 |
| `'R'` 的签名覆盖**整条记录**，包括恒为 0 的 `reserved0` | 记录里没有签名字段要排除，所以没有理由只签一部分。「签的就是板子要写的那几个字节」这条规则在这里可以做到一个不差 |
| `format_ver` 从第一版就存在 | 有了它，以后的格式变更是一次升级，不是一次破坏性迁移 |
| **没有兼容路径** | `record_is_structurally_valid()` 见到 `format_ver != 4` 直接判无效。v2 缺 uid、v3 的 `'R'` 是 160 字节还带签名和 generation —— 布局整个变了，而现场没有已认领的板子，所以这是硬切不是迁移 |

⚠️ **升到 v4 要重烧 bootloader 并重新认领。** 旧记录一条都不认。决策 72 把根区搬到扇区 15 时同样不迁移旧记录。

⚠️ **签名必须覆盖板子最终写进去的那几个字节，一个不差。** `uid` 那 12 字节是**板子自己从硬件 UID 填进记录的**，
不是工具送过来的 —— 上位机构造签名时必须预先算出板子将要写成什么样。差一个字节，板子重算时当场验不过。

### 根区为什么在扇区 15

H743 的擦除粒度是**整个 128K 扇区**。根区写满必须擦一次才能回收，所以它不能和 bootloader 同扇区 ——
那样每次回收都要重写 bootloader。

| 候选 | 结论 |
|---|---|
| 扇区 0 尾部（决策 72 之前的位置） | ❌ 回收要擦扇区 0，等于重写 bootloader，掉电就起不来 |
| 一个或两个专用扇区 | 可行，但 app 少 128–256 KiB |
| **扇区 15，并入它现有的「读出 → 擦 → 写回」回收** | ✅ **不多占 flash**；擦除期间根区暂存在备份 SRAM |

地址和回收步骤只写在 [扇区 15 设计说明](M1/SECTOR-15.md)。

⚠️ **扇区 0 从此只放 bootloader 代码**，`STM32H743IIKX_FLASH.ld` 的 `FLASH LENGTH` 不再需要为 owner 区让出 8K。

### 没有根时不告警，而是什么都不跑

决策 72 之前出厂板信一把公开根，所以每次启动要告警「任何人都能刷写」。
现在出厂板没有根：**不跑 app、不收上传，串口只提示「等待第一次上传认领」**。公开根指纹常量和 `report_root_trust()` 的告警一起删除。

### 这些东西住在哪

| 东西 | 住在哪 | 谁读 | 谁写 | core 要改吗 |
|---|---|---|---|---|
| **owner 根记录链** | 扇区 15 根区（[SECTOR-15.md](M1/SECTOR-15.md)） | boot；core 只读（`owner_root_ro.c`） | boot | 读取地址要跟着改 |
| 撤销状态 | 同上 | 同上 | boot | 同上 |
| 回收期间的暂存 | 备份 SRAM（[ARCHITECTURE.md](../repo/ARCHITECTURE.md) 的共享资源表） | boot | boot | 不用 |
| 证书 | 扇区 15 的 M 记录里 | boot | boot | 不用 |
| 用户的根私钥 | **PC 上**，见下一节 | IAPTool | IAPTool | 不用 |

**证书为什么可以和「会被擦的东西」同住**：它只需要验证*当前那个* app，
回收时最后一条 M 记录和根区一起被暂存、写回。

### 私钥放在哪

**板子上没有任何秘密**，只有用户根的公钥。私钥只在 PC 上：

| 事 | 做法 |
|---|---|
| 默认位置 | `<用户配置目录>/openplc/keys/fw_signing_key.pem`（`$TOOL/sign.go` 的 `userKeyLocation()`；Windows 上是 `%AppData%\openplc\keys\`）。不在板卡包目录里，升级板卡包不会删掉它 |
| 生成 | 第一次上传时本机没有就生成，**打印路径** |
| 读取 | 每次上传都**打印读的是哪个路径** |
| 换电脑 | 用户自己把根私钥拷到新电脑的默认位置 |
| 多人合用 | 根持有者用 `IAPTool cert` 给同事签发叶证书，见上面「发证书」 |
| 上传被拒 | 提示上面两条：拷根私钥，或向根持有者要叶证书 |

bootloader 原来的 `IAPServer/keys/` 目录（`fw_pubkey.inc`、`fw_signing_key.TEST_ONLY.pem`、`rotate_keys.sh`）随决策 72 整个删除。

### 两条实现上的硬规矩

**验签必须用 `owner_slot_root()`；它在没有根时返回「无」，调用者一律当作拒绝。** 编译进去的 `fw_public_key` 决策 72 之后不存在。

**core 侧有一份只读镜像**：`core:libraries/OpenPLC_IAP/src/owner_root_ro.{c,h}`，
把 owner 记录链的解析抄了一份出来，给需要知道「当前信任哪把根」但不写记录的 app 代码用。
**它的常量必须和 `$BOOT/IAPServer/owner_slot.h` 完全一致**，这条由跨仓镜像检查守着。

### BOOT0 手势：一次按压，三个结果

**恢复出厂不是另起一个手势，是现有那次按压的自然延长。** 十秒离 2 秒的判定点足够远，没人会因为「多按一会儿以防万一」而误触。

| 时刻 | 这一刻发生什么 | 此时松手的结果 |
|---|---|---|
| **0 s** | 复位，**系统指示灯快闪 2 秒**，串口打一行 ⁺ | — |
| **2 s** | **判定点：这一刻读一次引脚** | 没按下 ⇒ `NONE`，正常启动，按启动验签的结果决定跳 app 还是留在 bootloader |
| 1.5–10 s | 已进上传模式 | `UPLOAD` ⇒ `IAP_ALL`，CDC + 以太网全开 |
| **10 s** | **指示灯常亮 = 已武装** | `FACTORY_RESET`：追加一条 cleared 记录 ⇒ 回到没有根 |
| **30 s** | **判定卡键**（按键卡死或线短路） | 仍未松手 ⇒ 也当 `UPLOAD` 处理 |

```mermaid
flowchart TD
    R[复位] --> D{2 秒那一刻<br/>引脚按下了吗}
    D -->|没按下| N[NONE：正常启动]
    D -->|按下| U{什么时候松手}
    U -->|10 秒前| UP[UPLOAD：IAP_ALL]
    U -->|满 10 秒后| FR[FACTORY_RESET：回到没有根]
    U -->|超过 30 秒还没松| TO[判定卡键，当 UPLOAD 处理]
    style FR fill:#ffe6cc
    style N fill:#ccffcc
```

⚠️ **判定是「2 秒那一刻按键是否按下」，不是「按住了 2 秒」。** 指示灯快闪期间根本不看引脚 —— 全程按住只是**确保覆盖那一瞬间**的实用办法。

⁺ **开机不动任何继电器、DO、AO**：接了负载的输出每次上电都会被动作一次（[决策 71](../tables/DECISIONS.md)）。

⚠️ **按下的那一刻决定就定了**，后面发生什么都改不了它，只能**再加上一个恢复出厂**。

⚠️ **用声音不用灯**：这板子没有通用 LED，而且通常装在柜子里没人看得见。

⚠️ **顺序有讲究**：`owner_slot_factory_reset()` **必须在 `server_decide()` 之前调** —— 否则这次启动的日志会描述**刚被扔掉的所有权**，而这恰恰是唯一肯定有人在读日志的那次启动。

### 定下来的取舍

| | 结论 |
|---|---|
| 保留多大 | **8K**，`'O'` 32 条 + `'R'` 96 条 |
| 恢复出厂怎么触发 | **复位后按住 BOOT0 满 10 秒，看到指示灯常亮后松手**。不是另起一个手势，是现有 2 秒那次按压的自然延长 |
| 要不要上 WRP | **厂商不上，留给客户自己决定**（见第 6 节） |
| 认领要不要绑 UID | **绑。** 没有它，一块已认领板子的记录字节整段拷到另一块空白板上会被当成首次认领接受 |
| 会话认证走不走证书 | **走。** 板子上从此不存任何共享密钥。app 侧代价实测 +4.3KB，占可用 app 空间不到 0.3% |
| 证书 `serial` 谁分配 | **发证方本地的计数器**，文件就在根私钥旁边（`<key>.pem.certserial`）。⚠️ **这条 2026-09-20 已定要整个删掉**，见下 |

**自签证书不吃流水号，固定用 `0xFFFFFFFF`。** 编号当初留在这里，是为了「将来撤销时能点名」。

> ⚠️ **2026-09-20 起这个理由不成立了。** 撤销定成**按叶公钥点名，不按编号** ——
> `serial` 在板子侧没有任何作用（`iap_cert_verify()` 只把它算进签名，从不比对），
> **已定整个删掉**，证书 132 → 128 字节。决定和理由在
> [撤销记录点名的是序号还是公钥](../../maps/owner-revoke-and-boot-upgrade/issues/OWN-01-revoke-by-serial-or-by-pubkey.md)。
> **以下两条描述的是删除之前的现状。**

- 上传不碰计数器文件。那个文件在私钥旁边，对 Arduino 安装来说就在板卡包目录里 —— 一个上传流程本不该写入的地方
- **流水号写不进去时只报警告，不当错误** —— 一个没能持久化的流水号，比「拒绝签发证书」这件事小得多。⚠️ 正是这条让「换台电脑就静默撞号」成为可能，也正是**按编号撤销被否掉的原因**

¹³ **判定 2026-09-22 才有脚本和退出码。** 在那之前这条用例是四条命令加肉眼看日志，
所以没人说得出它上一次是什么时候过的。⚠️ 脚本**只判定，不换根** —— 换根那三步是破坏性的，
把它们塞进判定脚本里，就没法在不换根的情况下重新判一次。

¹⁴ **`T2-15` 那个 ✅ 不能顺延。** 反转前它验的是「撤销之后 app 起不来」，
反转后要验的是「撤销之后 app 照常起来」—— **同一块板上，一次通过正好是另一次的失败**，
所以状态退回 🟡 等真板子重跑。

⚠️ **它拒绝只凭「告警消失」就通过**：已认领的板子同样不告警，那是另一回事。
必须同时看见 `Owner slot: empty` 在、告警不在，而且要先看见一条**必然会打印**的行

¹¹ **`T2-22`–`T2-24` 在主机上跑，不上板，这是刻意的** —— `T2-22`/`T2-23` 要把 96 个作废名额
全部用掉，而那些名额**只有擦掉扇区 0 才能回收**，在唯一一块板子上做一次就再也做不了

是后补的，补完没有回头改小结。

⚠️ **`T2-01` `T2-03` 的动作走出货工具**（`IAPTool takeown` / `setowner`），**判据向板子要**（原始 TCP `getowner` / `getpubkey`）——
测的是客户真正会走的那条路，不是一个重新实现。
`T2-04` 是例外：出货工具做不出坏签名，所以那条在用例里手工拼记录。

⚠️ **委托证书分三段测**：`T1-18d`–`T1-18f` 用 bootloader 替身测**工具的**判断（替身是真 bootloader 代码，跑在 PC 上），

⚠️ **`T2-07` 的判据为什么不是「槽空就告警」** —— 自己编译固件的客户，owner 槽同样是空的，板子却是安全的。`owner_slot.c` 的 `report_root_trust()` 刻意只看**编进去的根是不是那把公开的**。所以这条用例要同时看见两件事：`Owner slot: empty` 在、告警不在。**只看告警没了是不够的** —— 日志没抓到也会是 0 行。

## 6 · 这个模块的边界

> **根区的安全上限 = 「这块板子上能不能跑任意代码」。**

| 状态 | 能不能跑任意代码 |
|---|---|
| **出厂状态（没有根）** | **不能。** 什么都不跑，只接受认领。但**第一次认领先到先得**（R1） |
| **已认领之后** | **不能。** 跑代码要先过签名，签名要 owner 私钥。从这一刻起 R2 是真保证 |

**挡不住什么**（写出来，因为不写就会有人以为挡得住）：

- **出厂板的第一次认领先到先得**：记录里 12 字节 `uid` 在签名覆盖范围内，所以已认领板子的记录整段拷到别的板上会被拒 —— 但出厂状态下谁先上传谁先认领
- **没上 flash 写保护（WRP）**，所以跑起来的 app 能写任何扇区，包括根区。WRP 在 RDP 0/1 下软件自己就能清除，只有 RDP 2 才冻结（RM0433 §4.5.2），而 RDP 2 会永久封死调试口、bootloader 也写不了扇区 15 —— **所以厂商不上，留给客户自己决定**
- **有物理接触的人可以恢复出厂后接管**（R3 挡不住的那条），这是刻意接受的

⚠️ **ST-Link 只重烧 bootloader 不再重置所有权** —— 根区在扇区 15，不在扇区 0。整片擦除才会连根区一起清掉，之后板子回到没有根。

**两条明确不做的**，理由在 [DEFERRED-DESIGNS.md](../tables/DEFERRED-DESIGNS.md)：

| 曾经的需求 | 为什么不做 |
|---|---|
| 产线给每块板发唯一密钥，取代固定密码 | 会话认证改走证书之后，板子里从此不存共享密钥，**产线预配随机密钥这条路没有存在的必要了** |
| flash 写保护（WRP）禁止 app 写 bootloader 区和根区 | 见上：RDP 0/1 下挡不住，RDP 2 又太锋利，留给客户 |

| 关系 | 去哪看 |
