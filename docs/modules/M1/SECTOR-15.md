# 扇区 15 设计说明

> ✅ **2026-09-21：代码已按这份实现并上板验收通过。**
> 实测：`Bootloader state: 28/3840 metadata slots used`，一次上传占 **7 格**。
> ⚠️ **仍未验证的只有一处** —— reclaim 搬运校准值那条分支，因为校准值区还是空的。
> 决策见 `DECISIONS.md` 第 61 条和[烧录前比版本 + 校准值住进扇区 15](../../../maps/version-gate-and-calibration/map.md)。
>
> **这份文件原名 `JOURNAL.md`。** 改名是因为事件日志删掉之后，这个扇区不再是 journal，
> 它装的是 firmware metadata 和校准值两样东西。

Flash 最后一个扇区（`IAP_STATE_SECTOR_ADDR` = `0x081E0000`，128 KiB）。
代码在 `IAPServer/bootloader_state.{c,h}`，判定链在 `IAPServer/IAP_server.c` 的 `server_decide()`。

## 它为什么存在

Bootloader 不能靠看 app 的头几个字节猜「这像不像一个合法程序」。旧版本就是这么干的 —— 看第一个字（MSP）像不像一个合理的 RAM 地址 —— **只要 flash 里恰好有个看着像栈指针的值，损坏的或被人写进去的镜像一样能通过。**

所以每次成功烧写要留下一份**出生证明**：大小、哈希的依据、签名、证书。下次上电拿它去核对。

⚠️ **所有规则都偏向保住 metadata。** 这个扇区里另一样东西（校准值）跟板子走、不跟固件走，两者的诉求相反 —— 下面的布局就是为了让它们互不干扰。

## 布局

```
0x081E0000  ┌─ 校准值区  8 KiB ─────────────────────────┐
            │  固定地址，不 append                       │
            │  工装经 JLINK 写；固件不提供写入命令        │
0x081E2000  ├─ metadata 区 120 KiB ─────────────────────┤
            │  append，一条 7 个 flash word = 224 B      │
            │  最后一条生效；容量 3840 格 ÷ 7 = 548 条    │
0x081FFFFF  └────────────────────────────────────────────┘
```

格子大小 **32 字节 = H7 的一个 flash word**，写入粒度下限，不能再小。

| 类型 | 首字节 | 占几格 | 内容 |
|---|---|---|---|
| `M` metadata | `0x4D` | **7** | `app_size` / `signature` / **整张证书** |
| 空 | `0xFF` | — | 擦除后的 flash |

M 记录占 7 格而不是 4 格，是为了把授权这个镜像的**那张 128 字节证书整条存进去** ——
只缓存叶公钥会让「换 owner 追溯作废固件」这条性质静默失效。

`_Static_assert` 锁死结构体尺寸。**这些尺寸就是 on-flash 格式** —— 多一个 padding 字节
会让已经写进去的每条记录的每个字段全部错位，所以让它编译失败，而不是运行时才发现。

## 三条写入路径

| 路径 | 谁在场 | 多久一次 | 擦什么 | 掉电后果 |
|---|---|---|---|---|
| **工装写校准值** | **人在场** | 出厂 + 偶尔重校 | 读校准值区到 RAM → 擦整扇区 → 写回 | 当场重来 |
| **升级写 metadata** | 无人值守 | 548 次里的 547 次 | **不擦**，纯 append | 校准值零风险 |
| **metadata 区满** | 无人值守 | 548 次升级一次 | 读校准值 8 KiB → 擦整扇区 → 写回校准值 + 一条新 metadata | ⚠️ **唯一的风险窗口** |

⚠️ **metadata 区满时不搬旧记录** —— 548 条里只有最后一条有用，旧的描述的镜像早已不存在。
要搬的只有校准值那 8 KiB。

⚠️ **那个风险窗口靠「工装按板子 UID 留一份校准值副本」兜住** ——
把后果从「回产线重新标定」降成「重写一次」。

### 为什么只有这两处能擦

擦 metadata 的那一刻，新镜像已经写进 app 区，**旧证明描述的东西已经不存在** ——
擦掉它不损失任何有效信息。而且在这里掉电，最坏结果是「需要重刷」，
**而这个结论从擦 app 区的那一刻起就已经成立了**。所以它不引入任何新的失败模式。

换到别处擦就不成立了。

## 上电：扫一遍

`bootloader_state_init()`：

```
从 metadata 区第一格往后扫
  │
  ├─ 0xFF（空）─────► 到头了，记下 next_free，结束
  │
  ├─ 'M'（7格）─────► last_metadata = 此处，i += 7，继续
  │                    （一路覆盖，所以最后留下的是最新那条）
  │
  └─ 其它 ──────────► 认不出，多半是旧版本布局写的
                       转为只读，等下一次成功上传时擦掉重来
```

**认不出就停，不猜长度往下走** —— 猜错一次就会落进别人记录的中间，之后读到的全是垃圾。

## 上电：拿它决定跳不跳

`server_decide()`：

```
crypto 自检过了吗？（sha256_selftest）
  │  否 ──► 一律当作无效。验证器本身都不可信，它的结论没有意义
  ▼
有 metadata 吗？
  │
  ├─ 没有 ─────────────────────────────────► app 无效
  │
  └─ 有 ──► app_size 在 (0, IAP_APP_MAX_SIZE] 吗？
             └─► 按 app_size 现算 app 区的 SHA-256
                  └─► 用 signature + cert 验签，并查这张叶有没有被撤销
                       ├─ 过 ───► app 有效 ──► 跳转进 app ✅
                       └─ 不过 ─► 停在 bootloader，身份报 BOOTLD-INVALID
```

**每次上电都验**，不是只在烧写后验一次 —— flash 会退化，也可能事后被改。

### 为什么是「验签」而不是「比对存好的哈希」

| | 只存哈希去比对 | 存签名去验证（现在） |
|---|---|---|
| 掉电半写、位翻转 | ✅ | ✅ |
| 有人重写 app 区 | ❌ **他也能把存的哈希一起改掉** | ✅ 没私钥签不出来 |

签名同时回答**完整性**（内容变了没有）和**真实性**（是不是持私钥的人签发的）。

⚠️ **它防的是损坏的镜像和远程注入，防不住手里拿着板子的人** —— 物理接触者可以用
ST-Link 直接重烧整片。这是刻意的取舍，见 `DECISIONS.md` 第 62 条。

## 被拒绝的认证只记在 RAM，绝不落 flash

**一次认证失败不会产生任何 flash 写入**，计数只活在 RAM 里（`s_auth_fail[32]` 环形缓冲）。

理由是拒绝服务：**未认证的调用者根本不该够得到 Flash** ——
否则一串被拒的命令就能磨损这个扇区，并逼出一次擦除。

⚠️ **这条和「八种事件日志全删」不是一回事** —— 那八种在 flash 上，这个在 RAM 里。
它的两个读取函数今天零调用者，**删不删单独定**，见
[烧录前比版本 + 校准值住进扇区 15](../../../maps/version-gate-and-calibration/map.md) 的迷雾。

## 「读不到 metadata」的两种情况

现象都是「停在 bootloader」，但原因不同。

| 情况 | 扫描时看到 | 串口现象 | 恢复 |
|---|---|---|---|
| **出厂空板 / 刚擦过** | 第一格就是 `0xFF` | `metadata absent` | 第一次上传就正常 |
| **上传中断 / 签名不过 / 叶被撤销** | 有 `M`，但验签失败 | `metadata present` + `App signature invalid` | 重传 |

⚠️ **事件日志删掉之后，这两种和「换了新 bootloader 读到旧布局」不再有独立的日志痕迹可查** ——
第三种会表现成第一种（旧记录认不出 → 擦掉 → 看起来像空板）。这是删日志的已知代价。

## 相对改动前的变化

下表左列是 2026-09-21 之前的行为，供查旧板子/旧日志时对照：

| | 改动前 | 现在（已实现并验过） |
|---|---|---|
| 扇区起点 | 整个 128 KiB 都是 journal，metadata 从 `0x081E0000` 起 | 前 8 KiB 给校准值，metadata 从 `0x081E2000` 起 |
| 事件日志 | **有**，八种事件、`'L'` 记录、`prev_hash` 防篡改链 | **全删** |
| 容量 | 4096 格，一次升级 8 格（7 + 1 条日志），约 512 次 | 3840 格，一次升级 7 格，**548 次** |
| 满了怎么办 | `journal_reclaim()` 整扇区擦，再记一条 `JOURNAL_RECLAIMED` | 先读出校准值 8 KiB，擦，写回校准值 + 新 metadata |
| 校准值 | **还没实现** | 固定地址，工装经 JLINK 写 |

**要查改动前的行为，用 `git log` 取回本文件改名前的版本** —— 它当时叫 `JOURNAL.md`，同目录，2026-09-21 随本次改名删除。
